Как прийти к решению за $O(n \log n)$: вывод из двумерной динамики

В записи этот вывод рассказывают второй преподаватель в середине лекции (, коротко) и ещё раз подробно после перерыва (, с доказательствами). Ниже — объединённый рассказ. Идея: решение с массивом $d$ — это двумерная динамика, у которой лишний параметр убрали.

Шаг 1. Типовая попытка и где она ломается. Для массива чаще всего пробуют динамику «по префиксу»: $dp_i$ — ответ на первых $i$ элементах. Но зная ответ на префиксе длины $i$, ответ для $i+1$ посчитать нельзя: мы не знаем, на каком значении заканчивается самая длинная подпоследовательность, а значит, не знаем, можно ли её продолжить числом $a_{i+1}$. В решении за $n^2$ эту проблему обходили определением «заканчивается ровно в $i$». Правило: если состояния не хватает, в него добавляют ещё один параметр.

Шаг 2. Кладём ответ в состояние. Добавим параметр $\ell$ — желаемую длину подпоследовательности — и в ячейке будем хранить то, что нужно для продолжения: наименьший возможный последний элемент. $$dp_{i,\ell} = \text{наименьший конец возрастающей подпоследовательности длины } \ell \text{ на первых } i \text{ элементах.}$$ Почему наименьший: чтобы подпоследовательность можно было продолжить числом $x$, важно только соотношение её последнего элемента с $x$; из подпоследовательностей одной длины лучшая — та, у которой конец меньше, так как ей подходит больше чисел. Ответ — наибольшее $\ell$, для которого $dp_{n,\ell} < +\infty$. База: $dp_{0,0} = -\infty$, $dp_{0,\ell} = +\infty$ при $\ell > 0$.

Шаг 3. Слои почти одинаковы. Если выписать массивы $dp_{i,\cdot}$ по слоям $i = 0, 1, 2,\dots$, видно, что соседние слои различаются не больше чем в одной ячейке. Тогда не нужно хранить все слои: достаточно одного массива, в котором на каждом шаге меняется одна ячейка. Так получается массив $d$ из прошлого раздела. Остаётся доказать, что слои действительно отличаются в одной ячейке, и понять, в какой.

Доказательство: что меняется при добавлении $a_{i+1}$

Переход от слоя $i$ к слою $i+1$ — добавление одного числа $a = a_{i+1}$. Либо мы его не используем (слой просто копируется), либо дописываем в конец какой-то подпоследовательности.

Лемма (возрастание слоя). Значения $dp_{i,0}, dp_{i,1}, \dots$ строго возрастают.

Доказательство (, от противного). Пусть $\ell_1 < \ell_2$ и $x_1 = dp_{i,\ell_1} \ge x_2 = dp_{i,\ell_2}$. Возьмём подпоследовательность длины $\ell_2$, заканчивающуюся на $x_2$. Её $\ell_1$-й по счёту элемент $y$ строго меньше $x_2$ (подпоследовательность строго возрастает, а $\ell_1 < \ell_2$), то есть $y < x_2 \le x_1$. Начало этой подпоследовательности до $y$ — возрастающая подпоследовательность длины $\ell_1$ с концом $y < x_1$. Но $x_1$ по определению наименьший возможный конец длины $\ell_1$ — противоречие. Значит, $x_1 < x_2$ для любых $\ell_1 < \ell_2$. $\square$

Что делает число $a$. Из строгого возрастания слоя следует: найдётся позиция $p$ — первая, где $dp_{i,p} \ge a$. Разобьём слой на две части: слева значения меньше $a$, справа не меньше.

  • Левая часть ($\ell < p$): не меняется. Здесь $dp_{i,\ell} < a$: у длины $\ell$ уже есть конец меньше $a$, а дописывание $a$ даёт конец $a$, то есть хуже. Помочь им нечем.

  • Позиция $p$: может измениться. Чтобы улучшить длину $p$, надо к подпоследовательности длины $p-1$ с концом меньше $a$ приписать $a$. Такая подпоследовательность есть: $dp_{i,p-1} < a$ (левая часть); причём $p \ge 1$, потому что $dp_{i,0} = -\infty$ меньше любого числа. Получаем подпоследовательность длины $p$ с концом $a$. Если $dp_{i,p} = a$, ничего не меняется; если $dp_{i,p} > a$, оно заменяется на $a$.

  • Правая часть ($\ell > p$): не меняется. Чтобы улучшить длину $\ell$, надо приписать $a$ к подпоследовательности длины $\ell - 1 \ge p$, у которой конец меньше $a$. Но все концы длины $\ge p$ не меньше $a$ ($dp_{i,\ell-1} \ge dp_{i,p} \ge a$). Так что приписать $a$ нельзя.

Вывод. Переход от слоя $i$ к слою $i+1$ меняет не более одной ячейки — первую, где $dp \ge a$ (находится бинарным поиском, это lower_bound), на значение $a$. Поэтому вместо таблицы $n \times n$ хранится один массив $d$, а каждое добавление числа стоит $O(\log n)$.

Из чата. Почему все значения $d$ остаются корректными после добавления $a_i$? Меняется ровно одна ячейка — для той длины, которую новое число может улучшить. Остальные остаются верны: для каждой из них уже существовала подпоследовательность с таким концом, мы ничего не сломали, а только, возможно, добавили более выгодную.
Из чата. Почему для 11 12 13 1 2 3 4 нельзя оставить 1 2 3 4 11 12 13? В $d$ хранятся не сами подпоследовательности, а концы: после трёх первых чисел $d = (-\infty, 11, 12, 13)$; единица заменяет $11$, двойка — $12$, тройка — $13$, четвёрка занимает первую бесконечность, получаем $d = (-\infty, 1, 2, 3, 4)$ и ответ $4$. Лектор подчёркивает, что $d$ не обязано хранить саму подпоследовательность: оно хранит лишь возможные концы.
Собственный пример. На массиве 11 12 13 1 массив $d$ станет $(-\infty,\ 1,\ 12,\ 13)$, а набор $1,\ 12,\ 13$ не является подпоследовательностью массива: единица стоит после двенадцати и тринадцати. Длина ответа ($3$) при этом верна — её даёт, например, $11\ 12\ 13$. Поэтому для восстановления подпоследовательности нужен отдельный массив $pr$ (см. ниже).

Восстановление самой подпоследовательности

Массив $d$ хранит лишь концы, но саму подпоследовательность восстановить можно. В каждый момент при добавлении $a_i$ мы выбираем позицию $p$ — запомним её в массиве $pr_i = p$. Это длина самой длинной подпоследовательности, оканчивающейся ровно в $a_i$ (то же, что $dp_i$ в решении за $n^2$).

  • Найдём максимальное значение $L = \max_i pr_i$ — длина ответа. Выберем любую позицию $i$ с $pr_i = L$. Если таких позиций несколько, для вывода какой-нибудь НВП подойдёт любая. Для лексикографически минимальной лектор советует брать самую правую из них (это замечание в конспекте не проверялось).
  • Идём справа налево и ищем первый элемент с $pr = L - 1$ — это предпоследний элемент ответа; затем ближайший левее элемент с $pr = L - 2$ и так далее. Найденные числа выписываем с конца и в конце переворачиваем.
Важное дополнение: почему «ближайший слева» подходит. Среди элементов с одинаковым $pr$ значения не возрастают при движении вправо: если бы $j < i$, $pr_j = pr_i = \ell$ и $a_j < a_i$, то $a_i$ можно было бы дописать после $a_j$, и $pr_i \ge \ell + 1$. Теперь пусть мы стоим в $i$ с $pr_i = \ell$. По определению есть какой-то $j < i$ с $pr_j = \ell - 1$ и $a_j < a_i$. Среди всех $j' < i$ с $pr_{j'} = \ell - 1$ самое правое имеет наименьшее значение (значения не возрастают вправо), значит, оно тоже меньше $a_i$ и подходит. Поэтому жадно брать ближайший слева — корректно.
// НВП с восстановлением ответа за O(n log n)
vector<int> lis_restore(const vector<int>& a) {
    const int INF = INT_MAX, NINF = INT_MIN;
    int n = a.size();
    vector<int> d(n + 1, INF), pr(n);
    d[0] = NINF;
    for (int i = 0; i < n; i++) {
        int len = lower_bound(d.begin(), d.end(), a[i]) - d.begin();
        d[len] = a[i];
        pr[i] = len;                   // длина НВП, оканчивающейся в a[i]
    }
    int L = *max_element(pr.begin(), pr.end());
    vector<int> res;
    int need = L;
    for (int i = n - 1; i >= 0 && need > 0; i--)
        if (pr[i] == need) {           // ближайший слева элемент нужной длины
            res.push_back(a[i]);
            need--;
        }
    reverse(res.begin(), res.end());
    return res;
}
Проверка. Обе версии (за $n^2$ и за $n \log n$ с восстановлением) сверены с полным перебором всех подпоследовательностей на 20 000 случайных массивов длины до 10: длины совпали, а восстановленная последовательность каждый раз оказывалась возрастающей подпоследовательностью исходного массива. На 3 7 6 10 8 9 ответ 3 6 8 9, на 11 12 13 1 2 3 4 — 1 2 3 4.

Наибольшая общая подпоследовательность (НОП)

Условие

Даны две строки $A$ и $B$. Нужно найти длину самой длинной строки, которая является подпоследовательностью (символы в исходном порядке, возможно, с пропусками) и $A$, и $B$.

Лектор поясняет на двух строках из букв A и B: общая подпоследовательность получается, если взять символы в том же порядке из обеих строк, пропуская лишние. Порядок нарушать нельзя, пропускать символы можно. Дальше строится динамика.

Определение, база, переход, ответ

  1. Определение. Первое предложение участника — хранить длину подпоследовательности, которая «в первой строке заканчивается в позиции $i$, а во второй в $j$» — лектор не принимает. Принято определение: $dp_{i,j}$ — длина наибольшей общей подпоследовательности префикса $A$ длины $i$ и префикса $B$ длины $j$ (нумерация с единицы, чтобы удобнее было обращаться к $i-1$).

  2. База. $dp_{i,0} = dp_{0,j} = 0$: у пустого префикса с любой строкой нет общих символов.

  3. Переход. Смотрим на последние символы префиксов $A_i$ и $B_j$.

    • Если $A_i = B_j$, этот символ можно поставить в конец общей подпоследовательности: к лучшему ответу на префиксах без этих символов добавляется единица. $$dp_{i,j} = dp_{i-1,j-1} + 1.$$
    • Если $A_i \ne B_j$, то хотя бы один из них в общей подпоследовательности не участвует, и мы выбрасываем один из двух последних символов, оставляя другой префикс целиком: $$dp_{i,j} = \max(dp_{i-1,j},\ dp_{i,j-1}).$$

  4. Ответ. $dp_{n,m}$, где $n = |A|$, $m = |B|$.

// dp[i][j] — НОП префиксов a[0..i) и b[0..j)
int lcs_len(const string& a, const string& b) {
    int n = a.size(), m = b.size();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));   // база: нули
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++) {
            if (a[i - 1] == b[j - 1]) dp[i][j] = dp[i - 1][j - 1] + 1;
            else dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
        }
    return dp[n][m];
}

Асимптотика. Состояний $n \cdot m$, переход за $O(1)$: время и память $O(nm)$. На вопрос, можно ли быстрее (за $O(n + m)$ или $O((n+m)\log)$), лектор отвечает отрицательно.

Почему при равных символах не нужен максимум из трёх

Участник спрашивает: при $A_i = B_j$ можно ли написать $\max$ из трёх значений — $dp_{i-1,j}$, $dp_{i,j-1}$ и $dp_{i-1,j-1}+1$? Можно, но не нужно. Лекторская версия объяснения (): если бы выгоднее было взять $dp_{i-1,j}$, то в ответе для префикса $A_{1..i-1}$ и $B_{1..j}$ последний символ $B_j$ уже совпал с каким-то более ранним символом $A$; но его можно сопоставить с $A_i$, ничего не потеряв. При неравных символах так сделать нельзя, и приходится искать равенство глубже в префиксах.

Развёрнутое объяснение. Строго: удаление одного символа из строки уменьшает НОП не более чем на единицу, поэтому $dp_{i-1,j} \le dp_{i-1,j-1} + 1$ и $dp_{i,j-1} \le dp_{i-1,j-1} + 1$. Значит, при $A_i = B_j$ значение $dp_{i-1,j-1}+1$ не меньше двух других, и максимум из трёх всегда равен ему. В другую сторону: достижимость $dp_{i-1,j-1} + 1$ очевидна — к любой общей подпоследовательности префиксов без последних символов дописываем общий символ.

Восстановление ответа

Пусть нужно вывести не только длину, но и саму НОП. Лекция называет два подхода (): обратный ход по таблице и массив родителей.

Обратный ход по таблице $dp$

Таблица уже содержит всю информацию о том, откуда мы пришли в клетку. Идём из $(n, m)$ к $(0,0)$:

  • если $A_i = B_j$, символ входит в ответ: записываем его и переходим в $(i-1, j-1)$;
  • иначе по формуле выбирался максимум: сравниваем $dp_{i-1,j}$ и $dp_{i,j-1}$ и переходим туда, где значение больше (в записи лектор описывает это как «в сторону большего»); в ответ ничего не добавляется;
  • идём, пока $i>0$ и $j>0$. Символы набираются с конца, поэтому в конце результат разворачивается ().

Лектор показывает на маленьком примере, как идёт обратный ход; в этом конспекте полный пример с таблицей и выделенным путём — на рисунке выше (собственный пример: строки ABCBD и BDCAB, ответ BCB).

Массив родителей

Второй способ: прямо в каждой клетке хранить пару индексов — откуда мы в неё пришли (). Тогда обратный ход не нужно «угадывать» сравнением значений: достаточно идти по родителям и добавлять в ответ символ тогда, когда переход был по диагонали при равных символах. Платим дополнительной памятью.

// НОП с восстановлением: обратный ход по таблице dp
string lcs_restore(const string& a, const string& b) {
    int n = a.size(), m = b.size();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i][j] = a[i - 1] == b[j - 1] ? dp[i - 1][j - 1] + 1
                                            : max(dp[i - 1][j], dp[i][j - 1]);
    string res;
    int i = n, j = m;
    while (i > 0 && j > 0) {
        if (a[i - 1] == b[j - 1]) {            // этот символ входит в ответ
            res += a[i - 1];
            i--; j--;
        } else if (dp[i - 1][j] >= dp[i][j - 1]) i--;   // идём туда, где больше
        else j--;
    }
    reverse(res.begin(), res.end());           // набирали с конца
    return res;
}
Проверка. Сверено с перебором всех подпоследовательностей на 20 000 случайных пар строк (длины до 8, три буквы): длина совпала, а результат каждый раз оказывался подпоследовательностью обеих строк. На ABCBD, BDCAB получается длина 3.
Важное дополнение: память. Если нужна только длина НОП, достаточно хранить две строки таблицы ($O(m)$ памяти). Для восстановления ответа полная таблица нужна (или более хитрые методы вроде алгоритма Хиршберга, который здесь не рассматривался).
Из чата. При равных $A_i$ и $B_j$ можно не смотреть на $dp_{i-1,j}$ и $dp_{i,j-1}$? Да: $dp_{i-1,j-1}$ уже включает всё нужное; см. разбор выше.
