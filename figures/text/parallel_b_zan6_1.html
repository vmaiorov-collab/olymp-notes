Разбор контеста по деревьям отрезков

Занятие начинается с разбора контеста по деревьям отрезков (лектор называет его «разбором в порядке возрастания сложности»). Условия задач звучат устно и напоминаются кратко; ниже они записаны так, как их пересказал лектор. Те задачи, которые были подробно разобраны на лекциях, даются только ссылкой на идею.

Задача C: независимо по битам

Решение сводится к одной фразе: задачу решают независимо по каждому биту. Для младшего бита, для следующего и так далее строится своё дерево отрезков, в вершине которого хранится информация для нулей и единиц. Ответ получается объединением результатов по всем битам. Тот же приём используется для любых побитовых операций: операции над разными разрядами между собой не связаны.

Задачи I, J: было на лекции

Задача I разобрана на лекции. Задача J — «напишите многомерный Фенвик» — тоже: многомерное дерево Фенвика обсуждалось на занятии, поэтому здесь не разбирается.

Задача D: копирование отрезков между массивами

Условие (как напомнил лектор). Даны два массива. Операция: взять отрезок второго массива и скопировать его в некоторое место первого. Запросы — узнать значение элемента первого массива.

Что хранить в дереве. В дереве отрезков хранятся индексы копируемых элементов второго массива. Если в позиции записано число $j$, значит, в этой позиции первого массива сейчас лежит $b_j$; значение $-1$ означает, что позиция не менялась и там осталось исходное число.

Чтобы скопировать отрезок, на заданном диапазоне первого массива нужно проставить арифметическую прогрессию с шагом $1$. Например, при копировании первых трёх элементов второго массива проставляются значения $0, 1, 2$; при копировании элементов со второго по четвёртый — $1, 2, 3$. Тогда запрос в первом массиве возвращает индекс элемента второго массива: если он равен $-1$, берём исходное число, иначе берём число из второго массива по этому индексу.

Проставление арифметической прогрессии разбиралось на предыдущей лекции. Так как шаг всегда один, в массовой операции достаточно хранить только первое число прогрессии (оно не всегда ноль).

Задача G: объединение прямоугольников

Задача разбиралась на лекции; лектор напоминает, что её можно решать двумя способами.

  • Сжатие координат (). В вершине дерева хранится минимум и суммарная длина элементов, на которых этот минимум достигается (а не просто их количество). Каждая вершина отвечает не за одну строку по координате $y$, а за целый блок строк определённой длины; поэтому количество минимумов заменяется суммарной длиной минимумов.
  • Неявное дерево отрезков (). Тогда сжимать координаты не нужно.

Задача F: три операции, всё сводится к арифметической прогрессии

В задаче три операции на дереве отрезков. Первая — прибавление числа на отрезке. Вторая — прибавление «шатра»: в центре отрезка прибавляется большое значение $X$, а в обе стороны оно убывает с шагом $d$. Фактически это две арифметические прогрессии: одна с шагом $+d$, вторая с шагом $-d$, причём вторая начинается с максимального значения $X$, а начало первой вычисляется ().

Прибавлять арифметическую прогрессию на отрезке умеем; остаётся «докрутить» операцию обычного прибавления. Лайфхак: представить обе операции как одну и ту же массовую операцию. Прибавление числа на отрезке — это прибавление арифметической прогрессии с шагом ноль. Поэтому все операции в дереве — это прибавление арифметической прогрессии, а запрос $get$ делается как обычно. Участник уточняет, что шаг прогрессии не обязан быть единицей; лектор отвечает, что от этого только проще — всё сводится к прибавлению арифметической прогрессии.

Задача E: сортировка подсчётом на отрезке

Условие. Дана строка и запросы «отсортировать подстроку на отрезке» ().

Используется сортировка подсчётом: на отрезке считаем количество символов каждого вида, затем присваиваем отрезки нужных символов. Лектор предлагает сравнить два варианта ():

  1. Одно дерево отрезков, в вершине которого хранится 26 чисел — количество каждого символа.
  2. 26 деревьев отрезков, каждое из которых отвечает за один символ (): там хранятся нули и единицы («здесь стоит этот символ»), нужны присваивание на отрезке и сумма на отрезке.

Во втором варианте для запроса сначала в каждом из деревьев выполняется $get$ — сколько символов этого вида на отрезке; затем в каждом дереве отрезок зануляется; затем в нужных деревьях нужный отрезок заполняется единицами.

Асимптотика. В первом варианте каждый запрос стоит $26 \cdot \log n$ на каждую операцию (в каждой посещённой вершине пересчитываются все $26$ чисел), а таких операций тоже $26$; итого размер алфавита в квадрате на логарифм: $O(26^2 \log n)$. Во втором варианте нет штрафа за пересчёт всех значений в каждой вершине: получается $O(26 \log n)$ на запрос. Второй вариант заходит точно и проще пишется (нули и единицы); первый, по словам лектора, тоже можно «упихать».

Урок. Иногда стоит следить за тем, сколько стоит одно слияние (merge) в вершине: если оно долгое, это влияет на асимптотику.

Задача H: НОД на отрезке при прибавлении

Запросы: прибавить число на отрезке и найти $\gcd$ на отрезке.

Идея. НОД набора чисел равен НОД любого одного числа из набора и всех чисел его разностного массива: $$\gcd(a_l, a_{l+1}, \dots, a_r) = \gcd\bigl(a_l,\ a_{l+1} - a_l,\ \dots,\ a_r - a_{r-1}\bigr).$$ Пример лектора: числа $7, 21, 49$ при разностях $14, 28$ дают $\gcd = 7$; если к разностям добавить, например, $49$, НОД остаётся равным $7$ (–).

Решение. Храним два дерева отрезков.

  • Первое хранит разностный массив. Прибавление $x$ на отрезке $[l, r]$ превращается в два обновления в точке: в левой границе плюс $x$, в правой минус $x$ (). Запрос — НОД на отрезке; он вычисляется как любая другая операция (функция «взять НОД левого и правого поддерева»). Это возможно именно потому, что обновление только точечное: для массового обновления нормального push здесь придумать нельзя.
  • Второе хранит исходный массив с обычными массовыми операциями (). Оно нужно, чтобы брать значение одного элемента отрезка и добавить его в НОД. Без него, например, при $7, 21, 49$ получился бы НОД разностей $14$ ().

Задача: взятие по модулю, присваивание и сумма

Запросы: взять числа на отрезке по модулю, присвоить значение, найти сумму на отрезке. Лектор напоминает идею, разобранную на лекции ():

Ключевое наблюдение. При взятии числа по модулю есть два варианта: либо оно не изменилось (было меньше модуля), либо уменьшилось хотя бы вдвое. Значит, без присваиваний каждое число изменилось бы не более $\log C$ раз ($C$ — максимальное значение), и всего изменений было бы не более $n \log C$.

Присваивание ничего не ломает. Присваиваний не более $Q$, поэтому в структуру за всё время попадёт не более $N + Q$ чисел ($N$ — исходные, $Q$ — верхняя граница тех, что будут присвоены), и каждое из них сократится не более $\log C$ раз. Итого операций модуля, меняющих числа, не более $(N+Q)\log C$.

Как реализовать. Есть два варианта.

  1. Явный. На отрезке находим максимум спуском; если он меньше модуля, операция заканчивается; иначе заменяем найденное число на нужное и повторяем (). Но тогда каждый спуск стоит $\log n$, и общая сложность умножается на $\log n$.
  2. За один спуск (). Если в текущей вершине максимум поддерева меньше модуля, менять в ней нечего. Если максимум не меньше модуля, спускаемся рекурсивно в обоих поддеревьях, обновляем их и пересчитываем текущую вершину. Асимптотически то же самое — работа пропорциональна числу изменённых вершин, — но константа гораздо лучше: один запрос на все вершины, а не отдельный запрос на каждое число; и пишется проще.

Задача: сколько отрезков накрывает хотя бы одну из заданных точек

Есть набор отрезков. В запросе приходит набор точек, нужно найти число отрезков, накрывающих хотя бы одну из них ().

Идея. Заранее посчитать для каждой точки, сколько отрезков её покрывает (это делается сканирующей прямой). Но просто сложить эти числа нельзя: отрезок, накрывающий сразу две точки, посчитается дважды. Поэтому идём по точкам слева направо и в каждой считаем только новые отрезки () — те, которые накрывают текущую точку и не накрывают предыдущую. Если отрезок накрывает текущую точку и уже был учтён, он гарантированно накрывает и предыдущую.

Новые отрезки = (все отрезки, накрывающие текущую точку) минус (отрезки, накрывающие весь промежуток между предыдущей и текущей точкой). Количество накрывающих точку известно, остаётся научиться отвечать на запрос: сколько отрезков накрывают весь диапазон $[L, R]$ ().

Как отвечать. Отсортируем отрезки по левой границе и выпишем их правые границы в этом порядке (). Тогда запрос «накрывают $[L, R]$» — это отрезки с левой границей $\le L$ (префикс этого массива, находится бинарным поиском) и правой границей $\ge R$ (). Остаётся посчитать на префиксе количество чисел $\ge R$: это делается Merge Sort Tree либо Wavelet Tree (). Вейвлет асимптотически быстрее, но MST тоже заходит.

Из чата. Участник предлагает более простое решение: спуск по дереву отрезков, где в вершине помечается, что в неё заходили; сбрасывать разметку между точками. Лектор говорит, что идейно оно легче, звучит нормально, но он его не сдавал и не может сразу подтвердить (). Сжимать координаты в этой задаче не нужно ().

Задача N: $k$-я порядковая статистика на отрезке

Нужно найти $k$-е по порядку число на отрезке. Первый шаг — бинарный поиск по ответу: нужно отвечать на вопрос «сколько на отрезке чисел меньше $x$».

  • Первое решение — MST. Получается $O(\log^2 n)$ на запрос MST, умноженное на $\log$ от бинпоиска, то есть $O(\log^3 n)$; этого достаточно.
  • Ускорение: заменить MST на Wavelet Tree. Тогда получается $O(\log n)$ от бинпоиска, умноженное на $O(\log n)$ запроса вейвлета, то есть $\log^2$.
  • И можно заменить бинарный поиск спуском по вейвлет-дереву — получится просто $O(\log n)$.

Лектор считает задачу «абсолютной халявой», хотя её сдали мало людей из-за тяжёлых условий.

Задача про исторический максимум

Условие. На отрезке операция «прибавить» и запрос «исторический максимум»: какое максимальное число когда-либо стояло на этих позициях ().

Это обычное дерево отрезков, в котором в вершине хранятся максимум и исторический максимум на отрезке.

В массовом обновлении без исторического максимума хранилось бы одно число: сколько добавить на отрезке — назовём его $add$. Теперь добавляется второе — $hadd$: максимальное значение добавки с момента предыдущего push (). Когда мы делаем push, исторический максимум «перетекает» в детей, и обе добавки обнуляются. Пока push не делается, при добавлении $x$ мы увеличиваем $add$ на $x$ и обновляем $hadd = \max(hadd,\ add)$.

Push. Лектор описывает его словами: при проталкивании сначала используем историческую добавку, затем обычную; ниже то же самое записано точно.

Развёрнутое объяснение. Пусть в вершине $v$ хранятся: $mx$ — текущий максимум, $hmx$ — исторический максимум, $add$ — отложенная добавка, $hadd$ — наибольшая «префиксная сумма» добавок с момента последнего push (то есть максимум из $0$ и всех частичных сумм). Чтобы применить к вершине пакет «добавка $a$, наибольшая частичная сумма которой $h$», достаточно четырёх присваиваний (порядок важен — сначала история, потом текущие значения): $$hmx \gets \max(hmx,\ mx + h),\quad mx \gets mx + a,\quad hadd \gets \max(hadd,\ add + h),\quad add \gets add + a.$$ push применяет к обоим детям пакет $(add_v,\ hadd_v)$ и обнуляет $add_v$, $hadd_v$. Обычная операция «прибавить $x$ на отрезке» применяет к полностью покрытой вершине пакет $(x,\ \max(x, 0))$. 
struct SegTree {
    int n;
    vector<long long> mx, hmx, add, hadd;
    // ... build: mx[v] = hmx[v] = a[l] в листе; pull: максимумы детей ...
    void apply(int v, long long a, long long h) {
        hmx[v]  = max(hmx[v],  mx[v]  + h);     // сначала история
        mx[v]  += a;                             // потом текущее значение
        hadd[v] = max(hadd[v], add[v] + h);
        add[v] += a;
    }
    void push(int v) {
        if (add[v] == 0 && hadd[v] == 0) return;
        for (int c : {2 * v, 2 * v + 1}) apply(c, add[v], hadd[v]);
        add[v] = hadd[v] = 0;
    }
    // update: если вершина целиком в отрезке — apply(v, x, max(x, 0LL)); иначе push, рекурсия, pull
    // query: исторический максимум — hmx[v] у полностью покрытых вершин, push при спуске
};
Проверено сравнением с перебором на 3 000 случайных массивов (до 40 операций каждый): ответы на запросы исторического максимума совпали.

Смысл задачи — показать, что в массовых операциях могут лежать нетривиальные величины и push может выглядеть нетривиально.

Из чата. Зачем в массовом обновлении хранить $hadd$? Пусть на отрезке стояли нули, мы сделали массовое «+5», затем «−5». Исторический максимум должен быть $5$. Но если ничего не пушили, текущая добавка равна $0$, и без отдельного $hadd$ эти две операции не были бы видны. Поэтому нужна «максимальная историческая префиксная сумма» добавок с момента последнего push. Если бы на моменте «+5» произошёл push, пятёрка уже ушла бы вниз.

Задача O: наименьшая сумма, которую нельзя набрать монетами на отрезке

Условие. Есть монеты с номиналами $a_i$. Запрос на отрезке: найти наименьшую сумму, которую нельзя набрать монетами этого отрезка ().

Сначала решаем задачу на всём массиве. Монеты рассматриваем в порядке возрастания номинала (порядок монет в массиве ни на что не влияет). Поддерживаем инвариант: умеем набирать ровно суммы от $1$ до $x$ и никакие другие. Изначально $x = 0$.

Рассмотрим очередную монету $y$.

  • Если $y > x + 1$, она не поможет: сумму $x+1$ набрать не получится. Если все оставшиеся монеты больше $x+1$, то ответ — $x + 1$ ().
  • Если $y \le x + 1$, монету использовать можно, и теперь набираются все суммы от $0$ до $x + y$ (). Почему: сумму $s \le x$ берём из прежнего набора; если $s > x$, берём монету $y$ и набираем $s - y$ из прежних, причём $0 \le s - y \le x$, так как $y \le x+1$ (–).

Запросы на отрезке. Начинаем с $x = 0$. На каждом шаге делаем запрос «сумма всех монет на отрезке со значением $\le x + 1$» () — это все монеты, которые могут пригодиться. Если сумма оказалась больше $x$, то $x$ становится равным этой сумме (). Важно присваивание «=», а не «+=»: эта сумма уже включает монеты, использованные ранее (). Если $x$ не изменился, ответ $x + 1$ ().

Сколько шагов. Не больше $2\log$ (по порядку величины — логарифм): пусть $x$ перешло в $x'$, затем в $x''$. В момент $x'$ уже использованы все монеты $\le x+1$; значит, при втором переходе добавилась монета, большая $x + 1$, и новая сумма не меньше $x + (x+1)$, то есть $\ge 2x$. За любые два перехода число удваивается, поэтому их не более $2\log C$ (–). Лектор отмечает, что эта оценка очень грубая.

Сумма монет $\le x+1$ на отрезке — это запрос «сумма чисел на отрезке не больше $v$»: MST или Wavelet Tree. MST проще пишется; вейвлет на практике ускоряет в два–три раза, а не в десятки (–).

Из чата. Откуда берётся условие «монеты $\le x+1$»? Если мы умеем набирать все суммы до $x$, полезны только монеты номиналом до $x+1$: монета $x+2$ не закрывает сумму $x+1$. Суммируем все такие монеты и говорим, что до этой суммы набирать умеем; повторяем, пока сумма не перестанет меняться.

Задача P: колода карт и запросы

Условие (как пересказал лектор). Колода карт задана перестановкой, например $1\ 4\ 3\ 5\ 2$. Дана последовательность запросов, например «3, 2, 2»: карты нужно получать именно в этом порядке. За одно действие можно взять верхнюю карту колоды и вставить её в любое место. Нужно минимизировать число действий, за которое выполняются все запросы (–).

Перефразировка. Очень важный шаг. Когда мы убираем карту, мы не вставляем её сразу в колоду, а откладываем в карман. Теперь за одно действие можно взять либо верхнюю карту колоды, либо любую карту из кармана. Позже строится последовательность действий, показывающая, что формулировки эквивалентны.

Жадность. Если нужная карта ещё лежит в колоде, берём карты сверху и откладываем их в карман, пока не получим нужную. Если нужная карта уже когда-то откладывалась, достаём её из кармана за одно действие. Так жадно симулируется весь порядок получаемых карт; ответ без восстановления — длина получившегося массива действий ().

Пример. Колода $1\ 4\ 3\ 5\ 2$, запросы $4, 5, 3, 4$. Идём до четвёрки: взяли $1$ и $4$. Хотим пятёрку: идём до пятёрки, выкидывая $3$ и $5$ (то есть откладываем их в карман). Тройка уже откладывалась — берём за одно действие. Четвёрка тоже откладывалась — берём за одно действие.

Восстановление: куда вставлять карту. Чтобы понять, куда в колоду надо сунуть карту, нужно посмотреть, когда она понадобится в следующий раз. Берём два её соседних вхождения в последовательность запросов и считаем количество различных чисел между ними (–). Ровно эти числа формируют «шапку» колоды до следующего появления нашей карты: они обязаны лежать выше (мы встретили их раньше), и ничего другого выше быть не может, иначе нам пришлось бы перебирать другие карты до нужной. Поэтому карту нужно вставить на глубину, равную числу различных на отрезке. Количество различных на отрезке считается MST или Wavelet Tree (–).

Другой взгляд: в каждый момент карты в колоде отсортированы по моменту, когда они в следующий раз будут использованы. Только что использованная карта должна лечь после тех, которые понадобятся раньше неё — отсюда тоже получается «число различных на отрезке» (–).

Задача B: параллелепипед и красные точки

Условие (как пересказал лектор). В трёхмерном пространстве даны точки, каждая помечена зелёной или красной: зелёные точки загаданный параллелепипед содержит, красные не содержит. Затем приходят независимые запросы — новая точка, и нужно ответить одно из четырёх: она обязательно входит в любой загаданный параллелепипед; обязательно не входит; может как входить, так и не входить; либо исходные данные некорректны (такая раскраска невозможна) (–). Трёхмерный Фенвик здесь не подходит из-за памяти ().

Проверка корректности. Строим минимальный возможный загаданный параллелепипед: по каждой оси берём минимум и максимум среди зелёных точек (независимо по каждой оси). Линейным проходом проверяем красные точки: если хотя бы одна попала внутрь, исходные данные некорректны ().

«Обязательно входит». Точка обязательно входит, если лежит в минимальном параллелепипеде (за $O(1)$ проверяется).

Различаем «обязательно не входит» и «может». Представим, что запрошенная точка тоже зелёная, и расширим минимальный параллелепипед до охватывающего зелёные точки и новую (по каждой оси берём минимум и максимум трёх значений). Если в расширенном параллелепипеде есть красная точка, то синяя зелёной быть не могла: «не может входить ни в какой загаданный». Если красных точек в нём нет, ответ «может» (–).

Итак, нужно отвечать на запрос «есть ли красные точки в трёхмерной области». В общем случае это сложно, но здесь любая запрошенная область содержит минимальный параллелепипед (он известен заранее и константен) ().

Разбиение на восемь частей. Область (расширенный параллелепипед минус минимальный) разбивается на восемь параллелепипедов: берём угол минимального параллелепипеда и противоположный угол расширенного и строим параллелепипед на этих двух точках. Всего восемь таких пар, и в объединении они дают расширенный параллелепипед (–). Нам достаточно, что красная точка нашлась хотя бы в одной из частей.

Оффлайн по группам. Для каждого запроса получаем по одному параллелепипеду в каждую из восьми групп, и в каждой группе у всех параллелепипедов общий угол — угол минимального параллелепипеда (). Именно этот факт позволяет отвечать на все запросы группы в оффлайне.

Ответ на запросы одной группы. Пусть общий угол перенесён в начало координат: нужно для каждого параллелепипеда с одним углом в $(0,0,0)$ понять, есть ли в нём красные точки (). Выбираем одну из осей и запускаем по ней сканирующую прямую: события — «добавляется точка» и «закрывается параллелепипед» (). После этого все запросы двумерные: добавление точки на плоскость и проверка, есть ли в области с углом в $(0,0)$ точки ().

Двумерный запрос решается одномерным деревом отрезков: по каждой строке храним самую левую точку (изначально $+\infty$). При добавлении точки делаем min= в точке. Чтобы проверить область, берём минимум на отрезке строк и сравниваем его с правой границей области (–).

Склеивать ответы не нужно. Запрос разбит на восемь частей, но объединять результаты не требуется: если в какой-то части нашлась красная точка, ответ записывается сразу в нужную позицию массива ответов (–). Лектор отмечает, что задача — скорее на реализацию, чем на идею ().

На этом разбор окончен; лектор напоминает, что остальные задачи контеста по идее несложные и пишутся легко, и объявляет начало лекции.
