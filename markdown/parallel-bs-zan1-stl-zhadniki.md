## 3. Устройство языка, которое пригодится в STL

### 3.1. Типы данных

Основные типы — `int`, `double`, `float` и другие. Кратко про неочевидные (): у `long long` диапазон от $-2^{63}$ до $2^{63}-1$ (в два раза больше разрядов, чем у `int`); у `int` 32 бита и диапазон от $-2^{31}$ до $2^{31}-1$; у `unsigned int` тоже 32 бита, но диапазон $[0,\,2^{32}-1]$.

`vector` и `string` различаются тем, что строка хранит символы (`char`), а у вектора тип элементов указывается в угловых скобках.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
vector<int> a(5, 5);                  // конструктор: размер 5, каждый элемент 5
vector<int> b = {5, 5, 5, 5, 5};      // список значений — получится то же самое
// vector<int> c{5, 5};              // осторожно: это два элемента (5 и 5), а не пять пятёрок
```

</div>

<div class="own">

<span class="lbl">Важное дополнение</span>\
Ловушка с фигурными скобками: `vector<int>(5, 5)` и `vector<int>{5, 5}` — разные вещи. Круглые скобки вызывают конструктор «размер, значение», фигурные задают список элементов.

</div>

### 3.2. Ключевое слово auto

`auto` позволяет не писать тип: компилятор выводит его из выражения. Например, `auto x = 5;` даст `int`. Особенно удобно с громоздкими типами: вместо `vector<pair<int,int>>::iterator` можно написать `auto`, а по вектору пройти циклом по диапазону.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
vector<pair<int, int>> v = {{1, 2}, {3, 4}};
for (auto p : v) cout << p.first << ' ' << p.second << '\n';
```

</div>

### 3.3. Передача по ссылке

Пусть функция печатает вектор. Когда вектор передаётся *по значению*, он копируется — за $O(n)$ на каждый вызов; можно получить непонятное превышение времени (TL). Если функция не должна менять вектор, его передают по константной ссылке; так же — строки и любые тяжёлые структуры.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
void print(const vector<int>& v) {      // ссылка: копирования нет
    for (int x : v) cout << x << ' ';
    cout << '\n';
}
```

</div>

К полю структуры обращаются через точку: `p.x`. Разница между `for (auto x : v)` и `for (auto& x : v)`: в первом случае каждый элемент *копируется*. Для `int` разницы практически нет, а для тяжёлых объектов копирование заметно замедляет цикл (лектор оценил: примерно вдвое); ссылка к тому же позволяет менять элементы.

## 4. Вектор

`vector` — динамический массив, умеющий сам расширяться. Объявление: `vector<int> v`; можно задать список элементов в фигурных скобках либо конструктором «размер, значение» (по умолчанию нули).

### 4.1. size и capacity

У вектора есть не только размер, но и **capacity** — сколько элементов поместится в уже выделенную память. `size` — число лежащих элементов, `capacity` — размер выделенного блока: это разные числа. Когда `size` становится равным `capacity`, при следующем `push_back` память выделяется заново, и `capacity` умножается на 2 (по-простому говоря).

> 🖼 Иллюстрация в оригинале: Размер и ёмкость — разные числа. Удвоение — не точное правило стандарта, а типичная реализация. (см. HTML-версию на сайте)

<div class="own">

<span class="lbl">Развёрнутое объяснение</span>\
`push_back` работает за амортизированное $O(1)$: удвоений происходит $\approx\log_2 n$, а суммарное число копируемых при этом элементов не больше $1+2+4+\dots<2n$. Точный коэффициент роста стандартом не задан (в разных реализациях 2 или 1,5), но вывод тот же.

</div>

### 4.2. Основные методы

`push_back(x)` добавляет элемент в конец; `emplace_back(...)` делает то же самое, но *конструирует* объект на месте: для вектора пар вместо `push_back(make_pair(1, 2))` достаточно `emplace_back(1, 2)`. `pop_back()` удаляет последний элемент, `clear()` очищает вектор.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
vector<pair<int, int>> v;
v.push_back({1, 2});
v.emplace_back(3, 4);      // сразу аргументы конструктора пары
v.pop_back();
v.clear();
```

</div>

## 5. Итераторы

Итераторы есть у вектора и почти у любого контейнера STL. Базовые: `v.begin()` — указатель на первый элемент, `v.end()` — на элемент *после* последнего. В STL почти всё работает на **полуинтервалах** `[begin, end)`: левая граница включена, правая — нет.

> 🖼 Иллюстрация в оригинале: Итератор — «указатель» на элемент. Разыменование даёт элемент, разность итераторов — расстояние. (см. HTML-версию на сайте)

У итераторов вектора можно прибавлять и вычитать числа и вычитать друг из друга: `v.begin() + 2` — итератор на элемент с индексом 2. Тип итератора громоздкий, поэтому удобно писать `auto`. Итератор можно *разыменовать*: `*it` — это сам элемент. Чтобы получить индекс элемента по итератору, нужно вычесть из него `v.begin()`.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
vector<int> v = {7, 3, 9, 5, 1};
auto it = v.begin() + 2;
cout << *it << '\n';                // 9
cout << it - v.begin() << '\n';       // 2 — индекс элемента
*it = 10;                              // через итератор элемент можно изменить
```

</div>

## 6. Сортировка и компараторы

Функция `sort(first, last)` принимает итераторы начала и конца полуинтервала. Третий параметр — **компаратор** — необязателен; без него используется оператор `<` и массив сортируется по возрастанию. Компаратор — булева функция от двух элементов, которая говорит, в каком порядке их расставлять: если `a` должен стоять раньше `b`, она возвращает `true`.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
bool cmpDesc(int a, int b) { return a > b; }   // по убыванию
sort(v.begin(), v.end());                         // по возрастанию
sort(v.begin(), v.end(), cmpDesc);                // по убыванию
// сколь угодно сложные условия, например по остатку:
// return a % x < b % x;
```

</div>

Главное условие, которому обязан удовлетворять компаратор: для одной и той же пары элементов он не может говорить «`a` раньше `b`» и «`b` раньше `a`» одновременно — не может быть, что `a` должен стоять раньше `b` и при этом `b` раньше `a`.

<div class="fix">

<span class="lbl">Уточнение</span>\
На записи условие сформулировано как «`cmp(a,b)` и `cmp(b,a)` должны возвращать разные значения». Это верно для *разных* по порядку элементов, но для равных (с точки зрения порядка) обе проверки должны вернуть `false`, и это нормально. Точное требование — «строгий слабый порядок»: `cmp(a,a)=false`; из `cmp(a,b)` следует `!cmp(b,a)`; транзитивность. Типичные ошибки: `return a <= b;` (при равных элементах оба вызова дают `true` — возможен вылет за границы массива) и непоследовательное сравнение нескольких полей.

</div>

### 6.1. Лямбда-функции

Лямбда — функция, объявленная прямо в месте вызова. В квадратных скобках указывается, какие внешние переменные она *захватывает*: пустые скобки — ничего не захватываем; `[&]` — всё по ссылке; `[x]` — переменную `x` по значению. Дальше как у обычной функции: параметры и тело.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
int x = 7;
sort(v.begin(), v.end(), [&](int a, int b) { return a % x < b % x; });
sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
```

</div>

## 7. lower_bound и upper_bound

`lower_bound` и `upper_bound` — это двоичный поиск, оформленный как готовая функция. Вызов `lower_bound(v.begin(), v.end(), x)` работает только на **отсортированном** диапазоне и возвращает итератор на *первый элемент, не меньший* $x$ (то есть $\ge x$); `upper_bound` — на первый элемент, *строго больший* $x$. Границы поиска — любые итераторы, не обязательно `begin` и `end` вектора.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
vector<int> v = {1, 3, 3, 5, 8};
auto lo = lower_bound(v.begin(), v.end(), 3);   // указывает на v[1]: первый элемент ≥ 3
auto hi = upper_bound(v.begin(), v.end(), 3);   // указывает на v[3]: первый элемент > 3
int cnt3 = hi - lo;                             // сколько троек: 2
```

</div>

Если все элементы меньше $x$, `lower_bound` вернёт `v.end()`; перед разыменованием это нужно проверять.

## 8. Сжатие координат

**Определение.** Есть массив $a_1,\dots,a_n$. Сжатие координат — преобразование его в массив $b_1,\dots,b_n$ такой, что: для любых $i,j$ из $a_i<a_j$ следует $b_i<b_j$; равные элементы остаются равными; при этом максимум массива $b$ минимален. Иначе говоря, числа заменяются номерами по порядку, а относительный порядок и равенства сохраняются.

Способов много, но самый хороший, «который надо писать»: отсортировать копию массива, воспользоваться функцией `unique` и для каждого элемента найти его место `lower_bound`-ом.

`unique` работает на *отсортированном* массиве: из каждой группы равных подряд идущих чисел оставляет одно (относительный порядок сохраняется), а остальные переносит в конец массива, и возвращает итератор на место, где заканчиваются уникальные. Сложность $O(n)$: функция один раз проходит массив и пишет в начало только новые значения. После неё «хвост» нужно отрезать.

> 🖼 Иллюстрация в оригинале: Числа 10, 30, 50, 90 получили номера 0, 1, 2, 3 — ровно по порядку возрастания. (см. HTML-версию на сайте)

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
vector<int> sorted_a = a;
sort(sorted_a.begin(), sorted_a.end());
sorted_a.erase(unique(sorted_a.begin(), sorted_a.end()), sorted_a.end());   // оставили уникальные
for (int& x : a)
    x = lower_bound(sorted_a.begin(), sorted_a.end(), x) - sorted_a.begin();  // номер среди уникальных
// итого O(n log n)
```

</div>

При разборе на доске в записи кода сначала чего-то не хватало — слушатель заметил, и код поправили. Два корректных варианта: `a.resize(unique(a.begin(), a.end()) - a.begin())` и `a.erase(unique(a.begin(), a.end()), a.end())` — второй удаляет всё, начиная с итератора, который вернул `unique`, до конца.

<div class="fix">

<span class="lbl">Уточнение</span>\
На записи сказано, что `unique` «возвращает размер». Точнее, она возвращает *итератор* на конец уникальной части; число уникальных элементов — это его разность с `begin()`.

</div>

## 9. Перестановки и заполнение массивов

`next_permutation(begin, end)` заменяет диапазон на следующую в лексикографическом порядке перестановку (необязательно настоящую перестановку чисел $1..n$ — подойдёт любой набор). Для $1\,2\,6\,4$ следующей будет $1\,4\,2\,6$: берётся наибольший хвост, который нельзя увеличить; предыдущий элемент меняется на наименьший больший из хвоста, а хвост сортируется по возрастанию. Функция возвращает `true`, если следующая нашлась, и `false`, если вся последовательность была наибольшей (тогда массив становится наименьшим — отсортированным).

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
vector<int> p = {1, 2, 6, 4};
next_permutation(p.begin(), p.end());      // p = {1, 4, 2, 6}
// перебор всех перестановок:
sort(p.begin(), p.end());
do { /* обработать p */ } while (next_permutation(p.begin(), p.end()));
```

</div>

`iota(begin, end, start)` заполняет диапазон значениями $start, start+1, start+2,\dots$ — удобно, чтобы получить тождественную перестановку и затем её переставлять (подробно — на лекции про перебор). `random_shuffle` (до C++17) и `shuffle(begin, end, gen)` перемешивают диапазон случайно, второй — с вашим генератором случайных чисел. `v.assign(n, x)` заполняет вектор: делает его размера $n$ из значений $x$.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
vector<int> a(5);
iota(a.begin(), a.end(), 0);                    // 0 1 2 3 4
mt19937 rng(12345);
shuffle(a.begin(), a.end(), rng);               // случайная перестановка
a.assign(7, -1);                                // семь элементов, равных −1
```

</div>

## 10. set, map и их собратья

### 10.1. set

`set` — множество: контейнер, хранящий элементы в *отсортированном* порядке, все элементы **уникальны**. `s.insert(x)` добавляет число (если оно уже есть, ничего не происходит), `s.erase(x)` удаляет (если нет — ничего не происходит).

### 10.2. map

`map` хранит по ключу значение: `m[key] = value`. Ключи уникальны и отсортированы по возрастанию. Во всех этих структурах порядок по умолчанию — по возрастанию; его можно изменить компаратором.

<div class="own">

<span class="lbl">Развёрнутое объяснение</span>\
Эти структуры реализованы сбалансированными деревьями поиска, поэтому `insert`, `erase`, `find`, `lower_bound` работают за $O(\log n)$. У `unordered_set` и `unordered_map` (хеш-таблицы) операции в среднем $O(1)$, но порядка нет и нельзя сделать `lower_bound`.

</div>

### 10.3. lower_bound у множества

В векторе мы писали `lower_bound(v.begin(), v.end(), x)`. Для множества так писать *нельзя* — вернее, оно заработает, но за $O(n)$: у итераторов множества нет операции «прибавить число», есть только `++` и `--`, и получить итератор на произвольную позицию за $O(1)$ нельзя. Поэтому у `set` есть собственный метод `s.lower_bound(x)` (и `upper_bound`), работающий за $O(\log n)$. У `map` тоже есть встроенные `lower_bound` и `upper_bound` — они ищут по ключу.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
set<int> s = {1, 4, 6, 9};
auto it = s.lower_bound(5);                // O(log n): итератор на 6
if (it != s.end()) cout << *it << '\n';
// lower_bound(s.begin(), s.end(), 5)      // компилируется, но работает за O(n) — не делайте так
// А ещё: нельзя вычитать итераторы друг из друга (s.end() - s.begin()) — это долго / не скомпилируется.
```

</div>

Сжатие координат можно сделать и через множество: закинуть все числа в `set` (повторы пропадут), затем пройти циклом и присвоить номера $0,1,2,\dots$ по порядку.

### 10.4. Как проверить, что x есть в множестве

Три способа: через `lower_bound` (итератор не должен быть `end` и должен указывать на $x$); через `s.count(x)` — число вхождений (для `set` это 0 или 1); через `s.find(x)` — итератор на $x$ либо `s.end()`. В C++20 добавили ещё `s.contains(x)`, возвращающий `true/false`. Всё это работает и в `map` (`find`, `count`, `contains`).

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
set<int> s = {1, 4, 6};
bool a1 = s.count(4);                       // 1
bool a2 = s.find(5) != s.end();             // 0
// bool a3 = s.contains(4);                 // C++20
```

</div>

## 11. multiset

`multiset` — то же, что `set`, но один элемент может встречаться несколько раз; элементы отсортированы.

**Количество элементов, равных $x$.** Метод `s.count(x)` работает за $O(\log n + k)$, где $k$ — число таких элементов, то есть в худшем случае за $O(n)$ — поэтому в цикле он может «убить» время. Лектор обращает внимание, что лучшего способа средствами одного `multiset` тут нет; а если нужны именно количества, выручает приём с `map` (см. ниже).

**Удаление.** `s.erase(x)` удаляет *все* вхождения $x$ (за их число). Чтобы удалить ровно одно вхождение, пишут `s.erase(s.find(x))` — стирание по итератору.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
multiset<int> ms = {1, 2, 2, 3};
ms.erase(ms.find(2));      // удалили ОДНО вхождение двойки: теперь {1, 2, 3}
ms.erase(2);               // удалили ВСЕ двойки: {1, 3}
```

</div>

<div class="own">

<span class="lbl">Важное дополнение</span>\
Если `x` нет в `multiset`, то `ms.erase(ms.find(x))` стирает `end()` — неопределённое поведение. Перед стиранием по итератору проверяйте, что итератор не равен `end()`.

</div>

### 11.1. Обход множества

Пробежаться по всем элементам можно циклом по диапазону или явно итераторами. Обход работает за $O(n)$: каждый шаг `++it` в среднем $O(1)$ (по дереву за все $n$ шагов — $O(n)$ в сумме).

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
for (int x : s) cout << x << ' ';
for (auto it = s.begin(); it != s.end(); ++it) cout << *it << ' ';
```

</div>

**Нельзя менять множество прямо в таком цикле.** Лектор предупреждает: если в цикле по диапазону добавлять или удалять элементы, итераторы «инвалидируются». Поэтому, если нужно пройтись и удалить часть элементов, сначала запоминают, что удалять, а удаляют после цикла. Альтернатива — искать следующий элемент двоичным поиском (`upper_bound`): обход получается за $O(n\log n)$, но удалять можно спокойно.

<div class="fix">

<span class="lbl">Уточнение</span>\
Для `set`/`map`/`multiset` на самом деле инвалидируются не все итераторы: вставка не портит ни одного итератора, а стирание портит только итераторы на *стёртый* элемент. Именно поэтому в цикле по диапазону нельзя стирать *текущий* элемент (после стирания цикл сделает `++` от недействительного итератора). Правильный шаблон стирания «на ходу»: `it = s.erase(it)`, в противном случае `++it`. У `vector` всё строже: любая вставка может перераспределить память и сделать недействительными *все* итераторы и ссылки.

</div>

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
// удалить из множества все чётные числа за один проход
for (auto it = s.begin(); it != s.end(); ) {
    if (*it % 2 == 0) it = s.erase(it);     // erase возвращает итератор на следующий элемент
    else ++it;
}
```

</div>

### 11.2. Лайфхак: map вместо multiset

Если программа с `multiset` не укладывается по времени, можно хранить `map<T, int>` — каждому значению сопоставлять его количество. Выигрыш виден, когда значений много, а различных мало: миллион единиц, миллион двоек и миллион троек — это три записи в `map` и три миллиона в `multiset`.

<div class="code">

<div class="code-head">

C++

копировать

</div>

```

// минимум: cnt.begin()->first;   максимум: cnt.rbegin()->first
```

</div>

## 12. stack, deque, queue

**stack** — «обрезанный» `deque`: умеет добавить в конец (`push`), удалить из конца (`pop`) и взять элемент конца (`top`). **deque** умеет работать с обоими концами: `push_back`, `pop_back`, `push_front`, `pop_front`, а также `front()` и `back()` — первый и последний элемент. **queue** (очередь) добавляет в конец и удаляет из начала; она пригодится в поиске в ширину (BFS).

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
deque<int> d;
d.push_back(1); d.push_front(2);           // [2, 1]
int f = d.front(), b = d.back();           // 2, 1
d.pop_front(); d.pop_back();               // пусто

queue<int> q;
q.push(5); q.push(7);                      // добавили в конец
int head = q.front(); q.pop();             // взяли и убрали из начала: 5
```

</div>

Лектор отмечает: `stack` почти всегда не нужен — это просто урезанный `deque`, он не быстрее, поэтому можно пользоваться `deque`. **Важное дополнение:** вместо стека подходит и обычный `vector` (`push_back`, `back`, `pop_back`) — обычно быстрее и без лишних функций.

## 14. Семинар: жадные алгоритмы

Начинают с простых задач: цель — в формате диалога научить решать даже совсем простые жадные задачи, а не просто выдать ответ. Если решение известно сразу, лектор просит дать подумать остальным.

### 14.1. Задача 1. Коробки

**Условие.** Дано $n$ коробок-кубов размеров $a_i$. Коробка $i$ помещается в коробку $j$, если $a_i<a_j$ (строгое неравенство — при равенстве было бы «слишком просто»); в одну коробку можно положить не более одной коробки *напрямую* (внутри может быть цепочка вложенных). Какое минимальное число коробок может остаться снаружи?

Примеры из записи: размеры $5,3,2$ — одна коробка (в пятёрку кладём тройку, в тройку — двойку); $5,3,2,5$ — две коробки. Сортировка решение не портит.

Из зала звучит несколько идей; их проверяют на примере вроде $5,5,6$ (ответ 2, а не 1) — это подводит к наблюдению про одинаковые коробки.

**Идея лектора.** Важно только *максимальное число одинаковых* коробок. Если все размеры различны — всё влезает в одну цепочку. В одной цепочке коробок две коробки одинакового размера лежать не могут, поэтому ответ не меньше $k$ — максимальной кратности. **Алгоритм:** отсортировать размеры и найти максимальное количество подряд идущих одинаковых; оно и есть ответ.

<div class="own">

<span class="lbl">Развёрнутое объяснение</span>\
**Нижняя оценка.** Коробки одного размера нельзя вложить друг в друга ни напрямую, ни через другие коробки (вложенные цепочки строго убывают), поэтому каждая из них — в своей цепочке: цепочек $\ge k$.\
**Построение.** Пронумеруем коробки каждого размера $1,2,\dots$ (если размера $s$ ровно $c_s\le k$ штук, номера $1..c_s$). Коробку размера $s$ с номером $j$ положим в цепочку $j$. В каждой цепочке не более одной коробки каждого размера, значит, отсортировав цепочку по убыванию, получаем корректное вложение. Итого $k$ цепочек — оценка достигается.

</div>

> 🖼 Иллюстрация в оригинале: Нижняя оценка — максимальная кратность $k$; конструкция из $k$ цепочек её достигает. (см. HTML-версию на сайте)

<div class="algo" data-frames="boxes">

</div>

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
int minBoxes(vector<int> a) {
    sort(a.begin(), a.end());
    int best = 0, run = 0;                       // run — длина текущей группы равных
    for (int i = 0; i < (int)a.size(); i++) {
        run = (i > 0 && a[i] == a[i - 1]) ? run + 1 : 1;
        best = max(best, run);
    }
    return best;                                 // максимальная кратность
}
```

</div>

Лектор проходит пример: размеры $1,2,2,3,3,3,5,5,6$ — максимальное количество одинаковых равно трём (три тройки), значит ответ 3. Затем та же задача формулируется «строго, без коробок»: массив $a_0,\dots,a_{n-1}$; можно «объединить» $a_i$ и $a_j$, если в $a_i$ ещё ничего не лежит и $a_i>a_j$; нужно получить как можно меньше элементов.

### 14.2. Задача 2. Экзамены

**Условие.** Студенту надо сдать $n$ экзаменов. Для каждого экзамена есть основная дата $a_i$ и запасная $b_i$ — сдавать можно в любую из этих двух. В зачётку преподаватель записывает *основную* дату $a_i$ экзамена — независимо от того, в какой день его реально сдали. Экзамены записываются в зачётку в порядке сдачи, и нужно, чтобы записанные даты не убывали. Требуется выбрать для каждого экзамена день сдачи (основной или запасной).

Пример: два экзамена с датами $(a_1,b_1)=(1,2)$ и $(a_2,b_2)=(2,1)$. Если сдать второй в день 1 (запись 2), а первый в день 2 (запись 1), в зачётке будет $2,1$ — убывание, недопустимо. Правильно: первый — в день 1 (запись 1), второй — в день 2 (запись 2).

<div class="fix">

<span class="lbl">Уточнение условия</span>\
На записи проговаривается, что в один день нельзя сдать два экзамена, но дальнейшее решение рассматривает не убывание записанных дат без строгости. Ниже разобран вариант «в один день можно сдать несколько экзаменов» (так в классической формулировке этой задачи). В варианте «не более одного экзамена в день» простая жадность с сортировкой пар по $(a,b)$ ломается, если у экзаменов совпадают основные даты, — пришлось бы дополнительно выбирать порядок среди таких.

</div>

**Идея.** Сортируем экзамены по возрастанию пар $(a_i,b_i)$ — это порядок записей в зачётке. Идём по ним и храним $x$ — *фактический день последнего сданного* экзамена. Для очередного экзамена есть три случая:

- если меньшая из дат $\min(a_i,b_i)\ge x$ — берём её (так $x$ становится минимальным из возможных);
- иначе, если большая дата $\max(a_i,b_i)\ge x$ — берём её;
- иначе ответа нет.

Лектор подчёркивает: сложную задачу разбили на три простых случая, а выбор жадный — на каждом шаге делаем $x$ как можно меньше.

<div class="own">

<span class="lbl">Развёрнутое объяснение</span>\
**Почему жадность верна.** Состояние после обработки префикса экзаменов полностью описывается числом $x$ — днём последнего экзамена. Чем меньше $x$, тем больше возможностей для следующих экзаменов: любое продолжение, допустимое при большем $x$, допустимо и при меньшем. Поэтому достаточно на каждом шаге получать наименьшее допустимое $x$ — это и делает алгоритм (берём наименьшую из двух дат, не меньшую $x$). Индукция: наш $x_i$ не больше соответствующего $x_i^*$ любого допустимого расписания.

</div>

<div class="code">

<div class="code-head">

C++

копировать

</div>

```
struct Exam { int a, b; };                                   // основная и запасная даты

int examSchedule(vector<Exam> e) {                           // последний день сдачи или -1, если невозможно
    sort(e.begin(), e.end(), [](const Exam& p, const Exam& q) {
        return make_pair(p.a, p.b) < make_pair(q.a, q.b);    // порядок записей: по a, при равных — по b
    });
    int x = 0;                                               // день последнего сданного экзамена
    for (const Exam& ex : e) {
        int lo = min(ex.a, ex.b), hi = max(ex.a, ex.b);
        if (lo >= x) x = lo;                                 // сдаём как можно раньше
        else if (hi >= x) x = hi;
        else return -1;                                      // ни одна дата не подходит
    }
    return x;
}
```

</div>

<span class="lbl">Проверка</span>\

### 14.3. Задача 3. Объединение королевств

**Условие.** Есть $n$ провинций, в $i$-й живёт $a_i$ человек. Две провинции $i$ и $j$ можно объединить в королевство: у него $a_i+a_j$ жителей. Паспорта лень обновлять: королевство берёт название большего, а жители меньшего получают новые паспорта — стоимость объединения $\min(a_i,a_j)$. Мы сами выбираем порядок объединений, нужно объединить все $n$ королевств в одно и *минимизировать суммарное число новых паспортов*.

Пример $1,2,3$: сначала объединить $1$ и $3$ (стоимость $\min=1$, получилось $4$), потом $4$ и $2$ (стоимость $2$) — всего $3$. Другой порядок: объединить $1$ и $2$ (стоимость $1$), затем $3$ и $3$ (стоимость $3$) — всего $4$.

**Ответ:** сумма всех чисел, кроме наибольшего (после сортировки — сумма первых $n-1$): объединяем всё в самое большое королевство. Лектор: в любом случае нужно ровно $n-1$ объединений, и минимальный размер первого объединения — минимальное значение, затем следующее и так далее; объединение в самое большое — всегда оптимально.

<div class="own">

<span class="lbl">Развёрнутое объяснение</span>\
Покажем, что любая последовательность слияний стоит не меньше $S-M$ ($S$ — общая сумма, $M$ — наибольший размер). Индукция по $n$. Последнее слияние делит провинции на две группы с суммами $S_1,S_2$ и максимумами $M_1,M_2$; по предположению индукции остальные слияния стоят $\ge(S_1-M_1)+(S_2-M_2)$. Само последнее слияние стоит $\min(S_1,S_2)\ge\min(M_1,M_2)$. Складывая: $\ge S-M_1-M_2+\min(M_1,M_2)=S-\max(M_1,M_2)=S-M$. Ровно столько стоит слияние «всё в наибольшее».

</div>

<div class="good">

<span class="lbl">Проверка</span>\
Формула «сумма всех, кроме наибольшего» сверена с перебором всех порядков слияний на 1000 случайных массивах (до 6 элементов, значения до 9).

</div>

### 14.4. Задача 3′. Стоимость объединения — сумма

**Усложнение.** Теперь при объединении *всем* жителям обоих королевств выдают новые паспорта: стоимость $a_i+a_j$. Как минимизировать сумму?

**Идея лектора:** на каждом шаге объединять два *наименьших* королевства. Лектор честно говорит, что эффект «на каждом шаге оптимально ⇒ в сумме оптимально» не гарантируется автоматически, и доказывать это строго тяжело; интуитивно «два маленьких, два маленьких…» — самое простое решение. **Совет по олимпиаде:** за пять часов не нужно строго доказывать всё, что вы пишете. Лектор вспоминает, как на региональном этапе написал пять жадных решений в задаче на динамическое программирование и набрал больше баллов, чем друзья с «нормальной» динамикой: у каждого жадного свои контрпримеры, но в сумме они компенсируют друг друга.

<div class="own">

<span class="lbl">Развёрнутое объяснение</span>\
Этот алгоритм известен как алгоритм Хаффмана. Корректность: стоимость равна $\sum_i a_i\cdot d_i$, где $d_i$ — глубина листа $i$ в дереве слияний (каждый житель платит по разу за каждое слияние, в котором участвует его королевство). Два самых лёгких листа можно «обменять» с двумя листьями на самой нижней глубине, не увеличив стоимость, так что в оптимальном дереве они — братья на самой глубине; склеив их, получаем ту же задачу на $n-1$ числах, к которой применяем индукцию.

</div>

#### Реализации

**Наивно, $O(n^2)$:** после объединения двух минимальных сумма кладётся на своё место сдвигом вправо свопами — вместо сортировки на каждом шаге ($n\log n$ каждый раз) получаем $O(n)$ на шаг: избавились от логарифма, но решение всё равно квадратичное. **Через `multiset`, $O(n\log n)$:** берём два минимальных, стираем, вставляем сумму.

```
long long mergeCostMultiset(const vector<long long>& a) {
    multiset<long long> s(a.begin(), a.end());
    long long ans = 0;
    while (s.size() > 1) {
        long long x = *s.begin(); s.erase(s.begin());      // наименьший
        long long y = *s.begin(); s.erase(s.begin());      // следующий
        ans += x + y;
        s.insert(x + y);
    }
    return ans;
}
```

</div>

**За $O(n)$, если числа уже отсортированы.** Без такого условия пришлось бы сортировать, и асимптотика всё равно была бы $n\log n$. Заведём второй массив-очередь $B$, куда будем класть получающиеся суммы. Ключевое наблюдение (): каждая новая сумма *не меньше* всех предыдущих (минимальная пара на каждом шаге только растёт), значит очередь $B$ сама остаётся отсортированной. Поэтому два наименьших числа всегда лежат среди «голов» очередей: это либо два первых необработанных числа массива $A$, либо два первых числа очереди $B$, либо по одному из каждой — всего три пары-кандидата.

> 🖼 Иллюстрация в оригинале: Достаточно смотреть на два первых числа в $A$ и два первых в $B$; общая сложность $O(n)$ при отсортированных входных данных. (см. HTML-версию на сайте)

```
long long mergeCostTwoQueues(vector<long long> a) {       // a отсортирован по неубыванию
    int n = a.size(), i = 0;                                // i — первый необработанный элемент a
    deque<long long> q;                                     // очередь сумм: тоже по возрастанию
    long long ans = 0;
    auto take = [&]() {                                     // достать наименьшее из голов a и q
        if (q.empty() || (i < n && a[i] <= q.front())) return a[i++];
        long long v = q.front(); q.pop_front(); return v;
    };
    for (int step = 0; step + 1 < n; step++) {
        long long x = take(), y = take();
        ans += x + y;
        q.push_back(x + y);
    }
    return ans;
}
```

</div>

Почему нельзя класть суммы прямо в массив $A$: мы не знаем, на какое место их ставить, а в очередь $B$ — знаем: каждая следующая сумма не меньше предыдущей и встаёт строго в конец. Если бы очередная сумма вдруг оказалась меньше предыдущей, значит, на предыдущем шаге взято неоптимальное действие — противоречие с тем, что мы всегда берём минимальную пару.

### 14.5. Задача 4. Восстановление строки

**Условие.** Есть строка $s$ из нулей и единиц длины $n$ и число $k$. По ней строится строка $v$ той же длины: $v_i=1$, если $s_{i-k}=1$ *или* $s_{i+k}=1$, и $v_i=0$, если оба равны нулю; если индекса $i-k$ или $i+k$ нет — соответствующий символ считается отсутствующим. Дана $v$ (и $k$); нужно вывести любую подходящую $s$ или сообщить, что такой нет.

<div class="note">

<span class="lbl">Вопрос из зала</span>\
Зачем во входных данных сначала записывают длину строки $n$? Лектор объясняет: при составлении тестов обычно пишут генератор, одним из параметров которого и является длина; а программе длина удобна — можно прочитать строку циклом ровно по $n$ символов, не проверяя «не конец ли строки» (это лишний код).

</div>

На записи сначала обсуждаются подходы «по цепочкам» (определять символы $s$ по уже известным и «прыгать» с шагом $k$), затем лектор разбирает идею одного из слушателей: смотрим на нули в $v$ — каждый нуль однозначно говорит, что $s_{i-k}=0$ и $s_{i+k}=0$ (если эти индексы существуют). Остальные символы $s$ можно положить равными единице: они ни на кого, кроме «разрешённых» единиц, не влияют. В конце обязательно *проверить*: построить $v$ по получившейся $s$ и сравнить с заданной — если не совпало, ответ «нет» (лектор: «вдруг мы где-нибудь запутаемся»).

> 🖼 Иллюстрация в оригинале: Нуль в $v_i$ обнуляет $s_{i-k}$ и $s_{i+k}$. Единицы везде, где обнулять не заставили, — это максимальная из подходящих строк. (см. HTML-версию на сайте)

<div class="own">

<span class="lbl">Развёрнутое объяснение</span>\
**Почему это верно.** Пусть $s^*$ — какая-нибудь подходящая строка. Каждый нуль $v_i$ заставляет $s^*_{i\pm k}=0$ — а наша $s$ нули имеет ровно в этих местах (и больше нигде), значит $s\ge s^*$ покомпонентно. Операция «или» монотонна, поэтому $v(s)\ge v(s^*)=v$. Для $v_i=0$ оба соседа в $s$ обнулены, поэтому $v(s)_i=0$, то есть $v(s)\le v$. Итого $v(s)=v$: если ответ вообще существует, наша $s$ — ответ; если проверка не прошла, подходящей строки нет. Сложность $O(n)$.

</div>

<div class="code-head">

```
// возвращает подходящую s или пустую строку, если такой нет
string restore(const string& v, int k) {
    int n = v.size();
    string s(n, '1');                                        // всё, что не заставили обнулить, — единицы
    for (int i = 0; i < n; i++) if (v[i] == '0') {
        if (i - k >= 0) s[i - k] = '0';
        if (i + k < n)  s[i + k] = '0';
    }
    for (int i = 0; i < n; i++) {                            // проверка: пересчитываем v по s
        bool one = (i - k >= 0 && s[i - k] == '1') || (i + k < n && s[i + k] == '1');
        if ((v[i] == '1') != one) return "";
    }
    return s;
}
```

</div>

## 15. Вопросы в конце занятия

**Организация.** После разбора три темы блока можно дорешивать в течение недели; запись занятия выложат как можно раньше, а разбор по этой теме будет через три недели. Дедлайн — неделя после разбора. **Вопрос:** нужно ли на туре доказывать жадный алгоритм? Лектор: если доказать быстрее, чем написать, — тогда да, но так бывает нечасто; жадные решения часто связаны с конструктивом и вырастают из «псевдодоказательства».

**Что такое «конструктив».** Сокращение от «конструктивное решение»: нужно предложить *какое-нибудь* подходящее решение, а не найти все. Например: «предложите тройку чисел, для которой $a^2+b^2=c^2$» — ответ $3,4,5$ достаточен, доказывать, что других нет, не требуется. Жадный алгоритм — когда вы придумываете идею и жадно набираете ответ; конструктивное решение — когда вы придумали идею и просто её реализуете, доказывая корректность.

**Переход в другую параллель.** Нужно написать преподавателям параллели, куда хочется перейти: они дают тест или просят решить определённое число задач.

**Как стать призёром Всероса (заключительного этапа ВсОШ).** Совет лектора: не нужно ничего «кардинально сложного» — верхняя граница — что-то вроде «до корнячка» (до корневой декомпозиции). Нужно *огромное количество прорешанных задач*: помогают Codeforces-раунды, дистанционные туры, а также умение не перегореть на самой олимпиаде. Математика: нужна база до определённого уровня — например, на региональном этапе в одной задаче надо было знать дискриминант; сложные геометрические теоремы и малая теорема Ферма не обязательны, полезнее задачи на логику.

**Сколько задач решать в день.** Лектор советует решать раунды на Codeforces не ради подготовки, а ради удовольствия: так вы дольше сохраните интерес к олимпиадным задачам. **Можно ли решать вместе.** Обсуждать идеи с другими слушателями можно и полезно, а вот вместе писать и скидывать код — нет.
