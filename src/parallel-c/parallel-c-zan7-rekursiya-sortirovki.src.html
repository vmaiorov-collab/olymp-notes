Рекурсия

1.1. Числа Фибоначчи

Рекурсия — когда функция (явно или через другие функции) вызывает саму себя. Классический пример — числа Фибоначчи, заданные рекуррентно: каждый член выражается через предыдущие, $F_n = F_{n-1} + F_{n-2}$. Чтобы такое определение работало, нужна база — несколько первых значений, заданных явно: $F_0=0$, $F_1=1$ (или, что то же самое, $F_1=F_2=1$). Дальше $F_2=1$, $F_3=2$, $F_4=3$, $F_5=5$, …

int fib(int n) {
    if (n == 1 || n == 2) return 1;          // база рекурсии
    return fib(n - 1) + fib(n - 2);          // вызываем саму себя
}

Код очевидно корректен (не считая того, что числа быстро растут и уже около $F_{47}$ переполняют int). Но он работает очень долго.

1.2. Почему наивная рекурсия экспоненциальна

Нарисуем дерево вызовов для fib(5): он вызывает fib(4) и fib(3); fib(4) снова вызывает fib(3) и fib(2), и так далее. Одно и то же значение — например, fib(3) — вычисляется много раз, и чем больше $n$, тем больше повторов: для fib(6) целиком пересчитывается вся работа fib(4) во второй ветке.

Если $T(n)$ — число шагов для $n$, то $T(n)=T(n-1)+T(n-2)$, то есть время растёт так же, как сами числа Фибоначчи, — экспоненциально (примерно $1{,}6^n$, асимптотически говорят «порядка $2^n$»). Проблема не в переполнении, а в том, что программа не успевает досчитать уже до нескольких десятков.

1.3. Мемоизация

Лечение: сохранять уже посчитанные значения и при повторном запросе возвращать их, не пересчитывая. Хранилище можно сделать глобальным (тогда функция всегда его видит, ничего не копируется) или передавать по ссылке. Используем map: заранее не нужно знать максимальное $n$.

map<int, long long> f;                       // уже посчитанные значения

long long fib(int n) {
    if (f.count(n)) return f[n];             // уже считали — просто вернуть
    if (n == 1 || n == 2) return f[n] = 1;
    f[n] = fib(n - 1) + fib(n - 2);          // считаем рекурсивно и кладём в кэш
    return f[n];
}

Важно вызывать именно fib(n - 1), а не читать f[n - 1]: при первом запросе соседних значений в кэше ещё нет, рекурсия их посчитает и положит туда. И не нужно дублировать строку с вычислением в return — это снова породит лишние вызовы.

Эта техника называется мемоизация (не «меморизация»). Каждое значение теперь вычисляется один раз, поэтому время — $O(n\log n)$ из-за map; с unordered_map или вектором заранее известного размера — $O(n)$. Ключом в map может быть и набор из нескольких параметров — это пригодится, когда у рекурсии их несколько.

Как это выглядит для fib(7). Сначала уходим по цепочке fib(6) → fib(5) → fib(4) → fib(3) → fib(2), fib(1); на обратном пути каждое значение записывается в кэш. Когда fib(4) просит fib(2), fib(5) — fib(3), а fib(7) — fib(5), ответ уже лежит в кэше, и целая ветка дерева не разворачивается. Порядок слагаемых (fib(n-2) + fib(n-1)) на асимптотику не влияет.

f.count(n) возвращает, сколько раз ключ встречается в map (0 или 1). В C++20 есть более наглядный f.contains(n), но на олимпиадах может оказаться старый стандарт. Зачем вообще писать это рекурсией, а не циклом, — тема следующего занятия.

1.4. Вывести последовательность в обратном порядке

Задача. Вводятся числа, заранее неизвестно сколько; признак конца — 0. Вывести их в обратном порядке, не сохраняя в вектор, массив или другую структуру. Например, для 1 10 2 4 6 5 7 0 ответ 7 5 6 4 2 10 1.

Функция read() обещает: «прочитать все числа до нуля и вывести их в обратном порядке». Тогда она читает очередное $x$; если это 0 — выходит; иначе сначала вызывает себя (та прочитает и выведет в обратном порядке весь хвост), а потом выводит $x$.

void read() {
    int x;
    cin >> x;
    if (x == 0) return;          // конец ввода
    read();                      // весь хвост уже выведен в обратном порядке
    cout << x << ' ';            // осталось вывести себя
}

1.5. Стек вызовов: память всё равно тратится

Магии нет. Каждое $x$ должно где-то жить, пока его не вывели. Локальные переменные функции хранятся на стеке вызовов: при вызове read() её переменные кладутся наверх, при возврате снимаются. Для ввода 1 2 3 4 0 на стеке одновременно лежат пять копий x; функция с нулём завершается первой, управление возвращается в функцию с четвёркой — та выводит 4 и завершается, и так далее.

На стек кладутся не только переменные, но и адрес возврата — куда продолжить выполнение после завершения. Поэтому рекурсия обычно тратит больше памяти и времени, чем то же самое с явным вектором; если памяти совсем нет, это решение тоже не сработает. Слово «стек» здесь — область памяти, а не std::stack.

Размер стека ограничивает операционная система. В тестирующих системах обычно разрешают стек размером с memory limit, так что рекурсия глубины $10^5$–$10^6$ в C++ проходит. В Python ограничение глубины по умолчанию маленькое, его приходится явно увеличивать.

Перебор с возвратом

2.1. Все двоичные строки длины $n$

Перебрать (и вывести) все строки длины $n$ из нулей и единиц. Для $n=3$ это 000, 001, 010, 011, 100, 101, 110, 111; для каждого следующего $n$ строк вдвое больше.

Храним одну текущую строку s и передаём её по ссылке — иначе на каждом вызове строка копировалась бы. Контракт функции: gen(n, s) перебирает все двоичные строки длины $n$, у которых уже зафиксировано начало s; она дописывает только оставшиеся символы.

  • Выход из рекурсии: если s.size() == n, строка готова — с ней можно сделать что угодно (вывести, сохранить) и обязательно выйти.
  • Шаг: поставить на следующую позицию 0, рекурсивно перебрать хвост, убрать 0; затем то же с 1.
void gen(int n, string& s) {
    if ((int)s.size() == n) {        // все символы зафиксированы
        cout << s << '\n';
        return;
    }
    s.push_back('0');                // выбираем 0 на текущую позицию
    gen(n, s);                       // перебираем хвост
    s.pop_back();                    // откатываем изменение
    s.push_back('1');
    gen(n, s);
    s.pop_back();
}

int main() {
    int n; cin >> n;
    string s;                        // gen(n, "") не скомпилируется: по ссылке
    gen(n, s);                       // нельзя передать временный объект
}

Откат изменений («возврат» к состоянию до выбора) и дал название перебор с возвратом (backtracking). Время — $O(n\cdot 2^n)$: строк $2^n$, каждую выводим за $O(n)$.

Временный объект по ссылке. Вызов gen(n, "") не сработает: функция хочет менять строку по неконстантной ссылке, а "" — только что созданный временный объект. Сначала заведите переменную, потом передайте её.

2.2. Строки ровно с $k$ единицами: отсечения

Теперь нужны строки длины $n$, в которых ровно $k$ единиц (например, для $n=4$, $k=2$: 1100, 1010, 1001, 0110, 0101, 0011). Перебрать все $2^n$ строк и выводить подходящие — слишком долго: при $n=100$, $k=2$ подходящих около 5000, а перебирать пришлось бы $2^{100}$.

Будем сразу отказываться от веток, которые к ответу не приведут. Передадим ещё cnt — сколько единиц уже поставлено (пересчитывать их по строке каждый раз дольше).

  • Ноль можно ставить, только если оставшихся позиций строго больше, чем недостающих единиц: n - s.size() > k - cnt. Если поровну, все оставшиеся позиции обязаны быть единицами.
  • Единицу можно ставить, только если их ещё не хватает: cnt < k.

Такие условия называются отсечениями.

void gen(int n, int k, string& s, int cnt) {
    if ((int)s.size() == n) {
        if (cnt == k) cout << s << '\n';   // проверка на всякий случай
        return;
    }
    if (n - (int)s.size() > k - cnt) {     // ноль не помешает добрать единицы
        s.push_back('0');
        gen(n, k, s, cnt);
        s.pop_back();
    }
    if (cnt < k) {                         // единиц ещё не хватает
        s.push_back('1');
        gen(n, k, s, cnt + 1);
        s.pop_back();
    }
}
Ловушка. В переборе всех строк можно было не делать pop_back, а просто перезаписать последний символ: s.back() = '1'. Здесь так нельзя: ветка с нулём может вообще не выполниться, и тогда перезаписывать нечего. Каждую ветку пишите независимо: положить, вызваться, убрать.

С отсечениями мы заходим только в ветки, ведущие к ответу, поэтому время пропорционально числу выведенных строк (умноженному на их длину). В задачах обычно гарантируют, что выводить нужно не слишком много.

2.3. Все перестановки

Перебрать все перестановки элементов массива: для $(1,2,3)$ это $123, 132, 213, 231, 312, 321$ — всего 6. Если в массиве есть равные элементы, будем переставлять именно позиции, а не значения.

Можно хранить множество свободных индексов в set, но проще так: пусть уже выбранное начало перестановки занимает первые позиции массива, а свободные элементы лежат в хвосте. На текущую позицию $pos$ перебираем любой элемент хвоста $i\ge pos$, меняем его местами с $a[pos]$ (выбранный встаёт на место, а прежний уходит в свободный хвост), рекурсивно достраиваем остальное и меняем обратно.

void gen(vector<int>& a, vector<int>& p) {     // p — уже выбранное начало
    if (p.size() == a.size()) {                   // перестановка готова
        for (int x : p) cout << x << ' ';
        cout << '\n';
        return;
    }
    int pos = p.size();                           // позиция, которую заполняем
    for (int i = pos; i < (int)a.size(); i++) {   // a[pos..] — свободные элементы
        swap(a[pos], a[i]);                       // a[i] занимает текущее место
        p.push_back(a[pos]);
        gen(a, p);
        p.pop_back();                             // откат в обратном порядке
        swap(a[pos], a[i]);
    }
}
Порядок важен. После push_back размер p меняется, поэтому позицию заранее сохраняем в pos. Откатываем изменения в обратном порядке: сначала pop_back, потом обратный swap. Вектор p можно вообще не заводить и передавать только pos: готовая перестановка и так лежит в a.

Перестановок $n! = 1\cdot2\cdots n$. Полезно помнить: $10!\approx3{,}6\cdot10^6$ перебрать можно, $11!$ — уже скорее всего нет.

2.4. next_permutation

В контесте к этому занятию перестановки нужно перебрать самостоятельно, рекурсией — для тренировки. А на олимпиаде проще воспользоваться стандартной функцией next_permutation(begin, end): она переставляет элементы в следующую по порядку перестановку ($12345\to12354\to12435\to12453\to\ldots$) и возвращает false, когда перестановки закончились.

sort(v.begin(), v.end());                        // начинаем с наименьшей перестановки
do {
    for (int x : v) cout << x << ' ';
    cout << '\n';
} while (next_permutation(v.begin(), v.end()));

Почему do … while, а не while (next_permutation(…)): обычный while сначала проверяет условие, то есть сразу сдвинет массив, и самая первая перестановка не будет обработана (при $n=1$ не будет обработано вообще ничего). do … while выполняет тело хотя бы раз и только потом проверяет условие; после закрывающей скобки условия ставится точка с запятой.

2.5. Убывающие последовательности

Перебрать все строго убывающие последовательности длины $n$ из чисел от 1 до $k$. Например, $5,4,3,1$ подходит, а $5,3,3,1$ и $1,2,3,4$ — нет.

Следующий элемент должен быть меньше последнего поставленного; если ещё ничего не стоит — не больше $k$. Перебираем кандидатов от большего к меньшему. Отсечение: если текущий кандидат $i$ меньше, чем количество элементов, которые ещё осталось поставить, то даже ставя дальше $i-1, i-2, \ldots$ мы не доберём длину — и меньшие $i$ тем более не подойдут, поэтому сразу break.

void gen(int n, int k, vector<int>& a) {
    if ((int)a.size() == n) {
        for (int x : a) cout << x << ' ';
        cout << '\n';
        return;
    }
    int mx = k;                                   // наибольшее, что можно поставить
    if (!a.empty()) mx = min(mx, a.back() - 1);   // строго меньше последнего
    for (int i = mx; i >= 1; i--) {
        if (i < n - (int)a.size()) break;         // хвост уже не достроить
        a.push_back(i);
        gen(n, k, a);
        a.pop_back();
    }
}

Благодаря отсечению перебираются только последовательности, которые дойдут до нужной длины, и время пропорционально размеру ответа. Здесь они выводятся от больших к меньшим; если в задаче нужен лексикографический порядок, перебор нужно немного переделать — это упражнение.

2.6. Разбиения числа на слагаемые

Перебрать все разбиения $n$ на положительные слагаемые, где порядок не важен: $1+2+3$ и $3+2+1$ — одно и то же. Чтобы не перебирать одно разбиение много раз, договоримся выписывать слагаемые по невозрастанию ($2+1+1$, но не $1+2+1$).

Очередное слагаемое не больше предыдущего (если оно есть) и не больше остатка суммы $n - sum$.

void gen(int n, vector<int>& a, int sum) {       // sum — сумма уже выбранных слагаемых
    if (sum == n) {
        for (int x : a) cout << x << ' ';
        cout << '\n';
        return;
    }
    int mx = n - sum;                             // больше остатка ставить нельзя
    if (!a.empty()) mx = min(mx, a.back());       // и не больше предыдущего слагаемого
    for (int i = mx; i >= 1; i--) {
        a.push_back(i);
        gen(n, a, sum + i);
        a.pop_back();
    }
}

Сортировки

3.1. Свойства сортировок

Квадратичных сортировок (пузырьком, вставками, выбором…) можно придумать сколько угодно, но на практике мы сортируем через std::sort с компараторами. Сегодня разберём сортировку, которая умеет то, чего std::sort не умеет. Сначала — по каким свойствам различают сортировки.

  • Дополнительная память. Быстрая сортировка (quicksort) сортирует на месте, без дополнительной памяти, но работает за $O(n\log n)$ лишь в среднем; при неудаче — за $O(n^2)$. Сортировка слиянием (merge sort) гарантирует $O(n\log n)$ всегда, но требует $O(n)$ дополнительной памяти. std::sort — не чистый quicksort и не чистое слияние, а комбинация нескольких алгоритмов, которая не деградирует до квадрата и не тратит много памяти.
  • Стабильность. Стабильная сортировка не меняет местами равные элементы. Если сортировать пары (имя, номер) только по имени, то «Петя 3, Петя 5, Петя 2» так и останутся в этом порядке. Сортировка слиянием стабильна, quicksort — нет. В C++ есть stable_sort: синтаксис как у sort, гарантирует стабильность, но использует больше памяти.

3.2. Сортировка слиянием: идея

Сортировка слиянием — самая простая из быстрых сортировок, при этом стабильная и работает для любых сравнимых объектов (чисел, строк, структур).

Предположим, у нас уже есть «магическая» функция, сортирующая любой массив. Как ею воспользоваться? Сортировать всё без первого элемента и вставлять его на место — получится квадрат. Правильно — делить пополам: рекурсивно отсортировать левую половину, рекурсивно отсортировать правую, а затем слить две отсортированные половины в одну. Массив из одного элемента уже отсортирован — это база.

Слияние мы уже умеем — это два указателя из занятия про объединение отсортированных последовательностей. Пример: $(1,2,3,3,7)$ и $(1,2,4,6)$. Каждый раз переносим меньший из текущих элементов; при равенстве берём из левой половины — так сортировка становится стабильной. Когда одна половина закончилась, дописываем остаток другой.

3.3. Реализация

void mergeSort(vector<int>& a) {                 // сортирует a на месте
    if (a.size() <= 1) return;                     // уже отсортирован
    int mid = a.size() / 2;
    vector<int> left(a.begin(), a.begin() + mid);  // копия левой половины
    vector<int> right(a.begin() + mid, a.end());   // и правой (полуинтервалы)
    mergeSort(left);
    mergeSort(right);
    int i = 0, j = 0, k = 0;                       // сливаем обратно в a
    while (i < (int)left.size() && j < (int)right.size()) {
        if (left[i] <= right[j]) a[k++] = left[i++];   // при равенстве — левый: стабильность
        else a[k++] = right[j++];
    }
    while (i < (int)left.size()) a[k++] = left[i++];   // дописываем остатки
    while (j < (int)right.size()) a[k++] = right[j++];
}

У вектора есть конструктор от двух итераторов: vector<int> left(a.begin(), a.begin() + mid) копирует элементы из полуинтервала $[\text{begin},\ \text{begin}+mid)$. Правая половина начинается ровно с a.begin() + mid, потому что правый конец полуинтервала не включается. Прибавление числа к итератору сдвигает его на столько позиций вперёд.

Время работы. На каждом уровне рекурсии массив разбит на куски суммарной длины $n$, а слияние работает за линию от размера — то есть каждый уровень стоит $O(n)$. Уровней столько, сколько раз $n$ можно поделить пополам до единицы, — $\log_2 n$. Итого $O(n\log n)$ времени и $O(n)$ дополнительной памяти; глубина рекурсии всего логарифм, так что разворачивать её не нужно.

3.4. Подсчёт инверсий

Инверсия — пара индексов $ia_j$. В массиве $(5,4,1,3,2)$ инверсии: $(5,4)$, $(5,1)$, $(5,3)$, $(5,2)$, $(4,1)$, $(4,3)$, $(4,2)$, $(3,2)$. Перебор всех пар — $O(n^2)$. Перечислять инверсии по одной тоже нельзя: в массиве, отсортированном по убыванию, их $\tfrac{n(n-1)}{2}$. Нужно считать их «пачками». Простая сортировка тут не поможет, а сортировка слиянием — поможет.

Инверсии внутри левой и внутри правой половины посчитаны рекурсивно. Осталось посчитать пары «левый элемент больше правого». Они обнаруживаются во время слияния: когда мы переносим элемент из правой половины (он строго меньше текущего левого), он «обгоняет» все ещё не перенесённые элементы левой половины — а они все не меньше текущего левого, то есть больше него. Значит, к ответу нужно прибавить left.size() - i.

Пример: половины $(1,4,5,7)$ и $(2,3,4,6)$. Переносим 1 из левой — инверсий нет. Переносим 2 из правой — она образует инверсии с $4,5,7$: $+3$. Переносим 3 — снова $+3$. Затем 4 из левой (при равенстве берём левый — равные элементы инверсию не образуют), 4 из правой — $+2$ (с 5 и 7), и так далее.

long long inv = 0;                                 // инверсий может быть ~n^2/2 — long long!

// в слиянии внутри mergeSort:
while (i < (int)left.size() && j < (int)right.size()) {
    if (left[i] <= right[j]) a[k++] = left[i++];
    else {
        inv += left.size() - i;                    // right[j] обгоняет все оставшиеся левые
        a[k++] = right[j++];
    }
}

Одна добавленная строка — и мы считаем число инверсий за $O(n\log n)$. При $n=10^5$ инверсий бывает порядка $5\cdot10^9$, поэтому счётчик — long long.

3.5. Сортировка подсчётом

Пусть все элементы — целые числа от 0 до $M$, где $M$ небольшое (скажем, $10^5$), а сам массив может быть длинным. Заведём массив cnt размера $M+1$: cnt[v] — сколько раз число $v$ встречается в массиве. Тогда отсортированный массив — это cnt[0] нулей, затем cnt[1] единиц, cnt[2] двоек и так далее.

vector<int> cnt(M + 1, 0);
for (int x : a) cnt[x]++;                          // сколько раз встречается каждое число
for (int v = 0; v <= M; v++)
    for (int t = 0; t < cnt[v]; t++)
        cout << v << ' ';                          // выводим v ровно cnt[v] раз

Время $O(n+M)$. Не подходит, если сортируем не числа (например, строки) или если числа большие — массив размера $10^9$ не заведёшь.

Вариант с map. Если чисел много, но различных мало, вместо массива подойдёт map<int, int> cnt: ключи в нём уже упорядочены, и можно пройтись по ним циклом for (auto [v, c] : cnt). Время — $O(n\log d)$, где $d$ — число различных значений. Например, при $n=10^5$ и всего 100 различных значениях это $10^5\cdot\log 100$, а не $10^5\cdot\log 10^5$, как у обычной сортировки.
