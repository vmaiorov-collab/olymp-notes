Делители числа

Теория чисел — про свойства целых чисел. На этом занятии почти всё крутится вокруг делителей: это фундамент для многих алгоритмов. Запись «$x$ делится на $y$» (пишут $x \,\vdots\, y$) означает, что $x = k\cdot y$ для некоторого целого $k$, то есть $y$ входит в $x$ множителем.

1.1. Делители разбиваются на пары

Делители числа 36 по возрастанию: $1, 2, 3, 4, 6, 9, 12, 18, 36$. Их можно разбить на пары с произведением 36: $(1,36)$, $(2,18)$, $(3,12)$, $(4,9)$, $(6,6)$. Чем больше один элемент пары, тем меньше другой, и пары «сходятся» к середине.

Это не совпадение. Если $y$ — делитель $x$, то и $\dfrac{x}{y}$ — делитель $x$, причём их произведение равно $x$. Значит, все делители любого числа разбиваются на пары $\left(y,\ \dfrac{x}{y}\right)$. Единственный особый случай — полный квадрат: у $36$ делитель $6$ стоит в паре сам с собой, потому что $36/6=6$.

1.2. Меньший в паре не больше $\sqrt{x}$

Утверждение. Если $a\cdot b = x$, то $\min(a,b)\le\sqrt{x}$.

Доказательство от противного. Пусть $\min(a,b) > \sqrt{x}$. Тогда и $a>\sqrt{x}$, и $b>\sqrt{x}$, а значит $a\cdot b > \sqrt{x}\cdot\sqrt{x} = x$. Но $a\cdot b = x$ — противоречие. Если $a\ne b$, неравенство строгое: меньший делитель в паре строго меньше корня, а равенство возможно только у пары $(\sqrt{x},\sqrt{x})$ для полного квадрата.

1.3. Перебор всех делителей за $O(\sqrt{x})$

Задача. Дано натуральное $x$, найти все его делители.

Наивно. Делитель не превосходит $x$, поэтому можно перебрать $d$ от 1 до $x$ и проверить x % d == 0. Это $O(x)$ — терпимо до $\approx10^5$–$10^8$, но не дальше.

Быстро. Перебирать нужно не все делители, а все пары. В каждой паре меньший элемент не больше $\sqrt{x}$, а больший однозначно восстанавливается как $x/d$. Поэтому достаточно перебрать $d$ от 1 до $\sqrt{x}$: каждый найденный $d$ даёт сразу пару $(d,\ x/d)$. Время — $O(\sqrt{x})$.

Без вещественных чисел. Условие d <= sqrt(x) плохо: корень — нецелое число, хранится неточно. Для неотрицательных чисел $d\le\sqrt{x} \iff d^2\le x$, так что пишем d * d <= x. Только не через pow(d, 2): pow тоже работает с вещественными числами. Просто умножьте $d$ на себя.

vector<long long> divs;
for (long long d = 1; d * d <= x; d++) {   // d — меньший делитель в паре, d <= sqrt(x)
    if (x % d == 0) {
        divs.push_back(d);
        if (d != x / d)                      // у полного квадрата пара (d, d) — не добавляем дважды
            divs.push_back(x / d);
    }
}
Полный квадрат. Если $x$ — полный квадрат, при $d=\sqrt{x}$ пара состоит из одного и того же числа. Без проверки d != x / d этот делитель попадёт в список дважды (это заметили в чате).

Насколько корень лучше линии. При $x=100$ корень — 10, при $x=40\,000$ — 200, при $x=10^{12}$ — всего $10^6$. Перебор до $10^{12}$ не выполнить никогда, а $10^6$ операций — мгновенно. Корень хуже логарифма ($\log_2 10^{12}\approx 40$), но гораздо лучше линии.

1.4. Проверка на простоту за $O(\sqrt{p})$

Число $p$ простое, если у него ровно два делителя: 1 и само $p$. Единица простой не считается: у неё один делитель. Первые простые: $2, 3, 5, 7, 11, 13, 17, 19, 23, \ldots$

Перебираем $d$ от 2 до $\sqrt{p}$. Если нашёлся делитель, у числа есть пара делителей помимо $(1,p)$ — оно составное. Если до корня делителей нет, то и после корня их нет (у каждого делителя больше корня пара меньше корня), значит $p$ простое. Пример: для $23$ проверяем $2, 3, 4$; при $d=5$ уже $25>23$ — останавливаемся, $23$ простое.

bool isPrime(long long p) {
    if (p == 1) return false;                // единица — отдельный случай
    for (long long d = 2; d * d <= p; d++)
        if (p % d == 0) return false;        // нашли делитель — составное
    return true;
}

Разложение на простые множители

2.1. Что это такое

Любое натуральное $x>1$ представляется в виде $x = p_1^{\alpha_1}\cdot p_2^{\alpha_2}\cdots p_m^{\alpha_m}$, где $p_i$ — простые, $\alpha_i>0$. Например, $36 = 2^2\cdot 3^2$, $17=17^1$, $30 = 2\cdot3\cdot5$.

Интуиция: раскладываем число на любые два множителя ($30 = 2\cdot 15$), потом каждый составной множитель — снова ($15=3\cdot 5$). Когда разложить дальше нельзя, все множители простые. Простые — это «атомы», из произведений которых состоят все числа.

2.2. Алгоритм за $O(x)$ и почему он находит только простые

Перебираем $d$ от 2 по возрастанию. Пока $x$ делится на $d$, добавляем $d$ в список множителей и делим $x$ на $d$.

vector<long long> primes;                    // простые множители с повторениями
for (long long d = 2; d <= x; d++) {
    while (x % d == 0) {                     // выкидываем d из x столько раз, сколько оно входит
        primes.push_back(d);
        x /= d;
    }
}

Мы перебираем все $d$, а не только простые, но добавляться будут только простые. Вся суть — в строке x /= d.

Почему так. Пусть в какой-то момент $x$ делится на составное $d$. Возьмём простой делитель $p$ числа $d$, тогда $pwhile на ней выкинул из $x$ все множители $p$. Значит, сейчас $x$ на $p$ делиться не может — противоречие. Итак, если $x$ делится на текущее $d$, то $d$ простое.

Пример: $x=20$. $d=2$: $20\to10\to5$, добавили $2, 2$. $d=3$: не делится. $d=4$: хотя исходное 20 делится на 4, все двойки уже выкинуты, осталось 5 — не делится. $d=5$: $5\to1$, добавили 5. Итог: $20 = 2\cdot2\cdot5$.

Интуитивно: $x$ — произведение простых. Мы идём по возрастанию и «вычёркиваем» из этого произведения сначала все двойки, потом все тройки и так далее. К составному $d$ его простые множители уже вычеркнуты, поэтому на него ничего не делится.

2.3. Ускорение до $O(\sqrt{x})$

Хуже всего, когда $x$ простое: тогда единственный множитель — само $x$, и цикл доходит до него. Как сделать $O(\sqrt{x})$ без отдельных проверок?

Выпишем простые множители по неубыванию: $x = a_1\cdot a_2\cdots a_n$, $a_1\le a_2\le\ldots\le a_n$. Утверждение: все множители, кроме, возможно, последнего, не больше $\sqrt{x}$. Достаточно показать это для предпоследнего $a_{n-1}$ — остальные не больше него.

От противного: если $a_{n-1}>\sqrt{x}$, то и $a_n\ge a_{n-1}>\sqrt{x}$, а тогда $a_{n-1}\cdot a_n > x$. Но это часть произведения, равного $x$, — противоречие.

Значит, перебрав $d$ до корня из исходного $x$, мы выкинем все множители, кроме, возможно, самого большого. В конце в $x$ останется либо 1 (все множители были не больше корня), либо ровно одно простое число больше корня — его добавляем отдельно.

vector<long long> factorize(long long x) {
    vector<long long> primes;
    long long x0 = x;                        // перебираем до корня из исходного числа
    for (long long d = 2; d * d <= x0; d++) {
        while (x % d == 0) {
            primes.push_back(d);
            x /= d;
        }
    }
    if (x != 1)                              // остался единственный множитель больше корня
        primes.push_back(x);
    return primes;
}
Это не про пары делителей. Здесь тоже перебор до корня, но обоснование другое: мы не ищем пары, а доказываем, что больше корня может быть не более одного простого множителя.
Подумать самостоятельно. Что изменится, если в условии цикла вместо исходного x0 писать текущее, уменьшающееся x (d * d <= x)? Будет ли алгоритм корректен и как изменится время работы?

Рекурсия для разложения не нужна: она тратит память и время на вызовы, а цикл ничем не хуже.

Модульная арифметика

3.1. Зачем нужны ответы по модулю

«$x$ по модулю $m$» — это остаток x % m. Взятие по модулю «зацикливает» числа: например, по модулю 3 все числа делятся на три класса по остатку, и каждое третье число считается «тем же самым».

Типы в C++ ограничены: int — примерно до $2\cdot10^9$, long long — примерно до $9\cdot10^{18}$, __int128 — ещё больше, но тоже конечен. А ответ в задаче может быть огромным (например, число сочетаний $C_{10^6}^{10^5}$). Поэтому часто просят вывести ответ по модулю — обычно $10^9+7$ или $998\,244\,353$. Жюри не различит $x$ и $x+m$, но при большом $m$ угадать правильный остаток случайно почти невозможно.

3.2. Операции по модулю

Главный факт: для сложения, вычитания и умножения можно брать остаток на каждом шаге — результат по модулю не изменится:

$$(a \circ b) \bmod m = \big((a \bmod m)\circ(b \bmod m)\big)\bmod m,\qquad \circ\in\{+,-,\cdot\}.$$

Доказательство для сложения. Запишем $a=\alpha m + x$, $b=\beta m+y$, где $x,y$ — остатки. Тогда $a+b = (\alpha+\beta)m + (x+y)$; часть, кратная $m$, при взятии остатка пропадает, и $(a+b)\bmod m = (x+y)\bmod m$. Для вычитания и умножения рассуждение аналогичное. С делением всё сложнее — оно будет в старших параллелях.

Поэтому, если ответ нужен по модулю, все промежуточные вычисления тоже ведём по модулю: числа остаются меньше $m$, и мы не переполняемся.

3.3. Вычитание: отрицательный остаток

В C++ остаток от отрицательного числа отрицателен: -7 % 5 == -2. А мы хотим жить в мире неотрицательных остатков $0,1,\ldots,m-1$. Числа, отличающиеся на кратное $m$, по модулю равны, поэтому пишем (a - b + m) % m.

3.4. Переполнение и функции-обёртки

Модуль не спасает от переполнения автоматически. При $m=10^9$ выражение a * b * c % m в long long переполнится: до взятия остатка появится число порядка $10^{27}$. Берите остаток после каждой операции: (a * b % m) * c % m. И выбирайте модуль так, чтобы $m^2$ влезало в тип: при $m=10^{12}$ даже произведение двух остатков уже не помещается в long long.

Когда операций по модулю много, легко где-нибудь забыть процент и потом полчаса искать переполнение. Удобнее один раз написать маленькие функции и дальше вызывать только их:

const long long MOD = 1e9 + 7;
long long add(long long a, long long b) { return (a + b) % MOD; }
long long sub(long long a, long long b) { return (a - b + MOD) % MOD; }
long long mul(long long a, long long b) { return a * b % MOD; }

// (a - b) * c + d по модулю — без единого ручного %
long long res = add(mul(sub(a, b), c), d);

Теперь корректность нужно обеспечить в трёх местах, а не в сорока.

Бинарное возведение в степень

4.1. Постановка и наивное решение

Нужно посчитать $a^x \bmod m$, где степень $x$ может быть очень большой, например до $10^{18}$. Без модуля задача неинтересна: результат быстро перестаёт помещаться в тип.

Наивно — $x$ раз умножить на $a$, каждый раз беря остаток. Это $O(x)$: при $x$ порядка $10^8$ ещё терпимо (взятие остатка — тяжёлая операция), но не больше.

4.2. Два факта

  • Факт «сложения»: $a^x = a^{x-1}\cdot a$.
  • Факт «умножения»: $a^{2p} = \left(a^p\right)^2$. Он следует из правила $(a^b)^c = a^{bc}$.

Второй факт сводит задачу для степени $2p$ к задаче для степени $p$ — вдвое меньшей. Пример для $x=18$: $a^{18}$ получаем возведением в квадрат $a^9$; $9$ нечётно, поэтому $a^9 = a^8\cdot a$; дальше $a^8\leftarrow a^4\leftarrow a^2\leftarrow a^1$ квадратами, а $a^1 = a^0\cdot a$, и $a^0=1$. Затем цепочка «раскручивается» обратно.

4.3. Сколько шагов: $O(\log x)$

Делить степень пополам можно не больше $\log_2 x$ раз. Если степень нечётна, вычитаем единицу — после этого она становится чётной, и следующий шаг снова делит пополам. Значит, перед каждым делением не больше одного вычитания, и всего шагов не больше примерно $2\log_2 x$. Итог — $O(\log x)$.

4.4. Реализация

long long binpow(long long a, long long p) {   // a^p по модулю MOD
    if (p == 0) return 1;                      // a^0 = 1
    if (p % 2 == 0) {                          // чётная степень: (a^(p/2))^2
        long long t = binpow(a, p / 2);
        return t * t % MOD;
    } else {                                   // нечётная: a^(p-1) * a
        long long t = binpow(a, p - 1);
        return t * a % MOD;
    }
}
Один рекурсивный вызов, а не два. Результат для $p/2$ сохраняем в переменную t и возводим её в квадрат. Если написать binpow(a, p/2) * binpow(a, p/2), задача уменьшится вдвое, но вызовов станет вдвое больше, и логарифм пропадёт: время станет не лучше линейного.
Опечатка с лекции. На доске сначала было написано «если степень нечётная — делим пополам»; это поправили из чата: пополам делим именно чётную степень.

НОД, НОК и алгоритм Евклида

5.1. Определения

НОД (наибольший общий делитель, $\gcd$) чисел $a$ и $b$ — наибольшее $c$, такое что $a$ и $b$ делятся на $c$. Примеры: $\gcd(3,2)=1$, $\gcd(12,9)=3$, $\gcd(16,8)=8$, $\gcd(36,24)=12$.

НОК (наименьшее общее кратное, $\operatorname{lcm}$) — наименьшее $c$, которое делится и на $a$, и на $b$. Примеры: $\operatorname{lcm}(3,2)=6$, $\operatorname{lcm}(12,9)=36$, $\operatorname{lcm}(16,8)=16$, $\operatorname{lcm}(36,24)=72$.

5.2. Вычитание сохраняет НОД

Пусть $g=\gcd(a,b)$, так что $a=g a'$, $b=g b'$. Если $a$ и $b$ делятся на $g$, то $a-b = g(a'-b')$ тоже делится на $g$. Отсюда (при $a\ge b$):

$$\gcd(a,b) = \gcd(a-b,\ b).$$

Почему НОД не вырос. Пусть у пары $(a-b,\ b)$ общий делитель $g'$. Тогда на $g'$ делится и сумма $(a-b)+b=a$, то есть $g'$ — общий делитель $a$ и $b$, а значит $g'\le g$. А делится она хотя бы на $g$ — значит НОД ровно $g$. Заодно полезно помнить: $0$ делится на всё, и $\gcd(x,0)=x$.

5.3. Алгоритм Евклида

Из большего числа вычитаем меньшее, пока оно остаётся не меньше меньшего, потом меняемся ролями. На каждом шаге одно из чисел уменьшается, поэтому рано или поздно одно из них станет нулём; другое в этот момент и есть НОД. Такая версия работает за $O(a+b)$.

Ускорение. Вычитать $b$ из $a$, пока $a\ge b$, — это ровно взятие остатка: если $a = q\cdot b + r$, то после серии вычитаний останется $r = a \bmod b$. Поэтому заменяем серию вычитаний одной операцией a %= b.

long long gcd(long long a, long long b) {
    if (a < b) swap(a, b);           // держим большее число в a
    while (b > 0) {
        a %= b;                       // вместо многократного a -= b
        swap(a, b);                   // остаток меньше b — меняем ролями
    }
    return a;                         // b стало нулём, a — это НОД
}

Время работы — $O(\log\max(a,b))$: взятие остатка уменьшает большее число хотя бы вдвое, поэтому шагов логарифм. В C++17 есть готовая функция std::gcd.

5.4. НОК через НОД

$$\operatorname{lcm}(a,b)=\frac{a\cdot b}{\gcd(a,b)}.$$

Идея через простые множители: в НОК должны войти множители, которые есть только в $a$, только в $b$, и общие. В произведении $a\cdot b$ общие множители учтены дважды (из $a$ и из $b$), и лишнюю копию убирает деление на НОД — он состоит ровно из общих множителей. Произведение на НОД делится нацело, потому что на него делится уже само $a$.

Проверка. $\operatorname{lcm}(36,24) = 36\cdot24/12 = 72$, $\operatorname{lcm}(12,9)=108/3=36$ — совпадает с примерами выше.
Порядок операций. Чтобы произведение $a\cdot b$ не переполнилось на больших числах, удобнее считать a / gcd(a, b) * b — сначала деление, потом умножение.

Решето Эратосфена

6.1. Задача и идея

Найти все простые числа, не превосходящие $n$. Проверять каждое число за корень — это $O(n\sqrt{n})$; хочется быстрее.

Идея. Составное число делится на какое-то меньшее простое. Идём по числам по возрастанию; если текущее число ещё не вычеркнуто, оно простое — и тогда вычёркиваем все числа, кратные ему. Двойка: вычёркиваем 4, 6, 8, … Тройка не вычеркнута — простая, вычёркиваем 9, 15, … (6 и 12 уже вычеркнуты). Пятёрка, семёрка — и так далее. Название от того, что в древности числа писали на табличке и прокалывали составные — получалось «решето».

6.2. Реализация за $O(n\log n)$

Если для каждого простого $d$ проверять все числа от $d$ до $n$ на делимость, выйдет $O(n^2)$. Вместо этого сразу перебираем только кратные: $2d, 3d, 4d, \ldots$ — следующее после кратного $d$ кратное равно ему плюс $d$.

vector<bool> prime(n + 1, true);
prime[0] = prime[1] = false;
for (int d = 2; d <= n; d++) {
    if (!prime[d]) continue;                         // составные не вычёркивают
    for (int num = 2 * d; num <= n; num += d)        // идём только по кратным d
        prime[num] = false;
}

Оценка. Для $d=2$ внутренний цикл делает $n/2$ шагов, для $d=3$ — $n/3$ и так далее. Сверху всё ограничено суммой $n\left(\tfrac12+\tfrac13+\ldots+\tfrac1n\right)$.

Уменьшим знаменатели до ближайшей степени двойки — сумма от этого только вырастет: $\tfrac12+\tfrac12+\tfrac14+\tfrac14+\tfrac14+\tfrac14+\tfrac18+\ldots$ Каждая группа $\underbrace{\tfrac1{2^k}+\ldots+\tfrac1{2^k}}_{2^k}$ даёт 1, а групп около $\log_2 n$. Значит, сумма не больше $\log_2 n$, и всё решето работает за $O(n\log n)$ времени и $O(n)$ памяти.

6.3. Оптимизация: начинать с $d^2$

Вычёркивать можно начинать не с $2d$, а с $d\cdot d$. Любое составное число меньше $d^2$ имеет простой делитель меньше $d$ и уже вычеркнуто раньше. Тогда время работы становится $O(n\log\log n)$ — это утверждение даётся без доказательства. Оптимизация бесплатная: меняется только начальное значение во внутреннем цикле.

for (long long num = 1LL * d * d; num <= n; num += d)
    prime[num] = false;
Тип. При $d$ порядка $10^5$ произведение $d\cdot d$ уже не помещается в int, поэтому квадрат считаем в long long.
