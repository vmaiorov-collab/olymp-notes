Разбор контеста по корневой декомпозиции

1.1. Суровый корректор

Дана большая строка $S$ и много «интересных» строк $t_i$ (их суммарная длина $L$ порядка $10^5$). Запрос: отрезок $S[l..r]$ — сколько раз в него суммарно входят все интересные строки. Делим строки на тяжёлые (длина больше $\sqrt{L}$, их не больше $\sqrt{L}$) и лёгкие.

  • Для каждой тяжёлой строки заранее находим все её вхождения в $S$ (хешами или префикс-функцией) и отвечаем на запрос суммой на отрезке позиций начала.
  • Длина лёгкой строки не больше $\sqrt{L}$. Перебираем каждую длину от 1 до $\sqrt{L}$, считаем хеши всех подстрок $S$ этой длины и для каждой позиции отмечаем, начинается ли там интересная строка. На запрос отвечаем суммами на отрезке для каждой длины, не вылезая за правую границу.

1.2. Мячик и прыжки по массиву

В ячейке $i$ записана длина прыжка $a_i$; мяч, попав в ячейку, прыгает вперёд на $a_i$. Запросы: изменить $a_i$; бросить мяч в ячейку и узнать, из какой ячейки он вылетит за массив.

Делим массив на блоки по $\sqrt{n}$. Для каждой ячейки храним, в какую ячейку мяч впервые попадёт за пределами своего блока (и сколько прыжков на это нужно). Это считается внутри блока справа налево за размер блока. Запрос: прыгаем блоками, каждый блок за $O(1)$ — всего $O(\sqrt{n})$. Изменение пересчитывает только один блок за $O(\sqrt{n})$.

1.3. Варенье: прибавления прогрессий

Массив $A$ изначально нулевой; запросы прибавляют на отрезке арифметическую прогрессию. Есть массив $B$. Для каждой позиции $i$ нужно узнать, после какого запроса впервые $A_i\ge B_i$.

Разбиваем запросы на $\sqrt{q}$ блоков. Применяем блок целиком сканлайном (разностные массивы второго порядка) за $O(n+\sqrt q)$ и проверяем все позиции. Если позиция только что впервые «перешла» $B_i$, откатываемся к состоянию до блока и для этой позиции честно применяем запросы блока по одному, пока не найдём нужный. Для каждой позиции такой точный проход делается один раз. Итого $O\big((n+q)\sqrt{q}\big)$.

1.4. Глеб и медиана

Запросы: изменить элемент; для отрезка $[l,r]$ и числа $M$ найти максимальное $k$, такое что отрезок можно разбить на $k$ кусков, у каждого из которых медиана не меньше $M$.

Важный трюк для медиан: заменим числа $\ge M$ на $+1$, а меньшие $M$ — на $-1$. Тогда медиана отрезка не меньше $M$ тогда и только тогда, когда сумма на нём неотрицательна. Максимальное число кусков с неотрицательной суммой из $\pm1$ — это просто сумма всего отрезка (если она положительна). Значит, ответ — (число элементов $\ge M$) минус (число элементов $<M$), и задача сводится к подсчёту на отрезке элементов, меньших $M$, с изменениями в точке — корневой декомпозицией.

1.5. Делители на отрезке

Запросы: изменить элемент; посчитать на отрезке $[l,r]$ элементы, которые делят $x$. При $x\le10^5$ у числа не больше 128 делителей, так что достаточно уметь считать количество элементов, равных заданному $d$, на отрезке. Решение с ordered_set на каждое значение даёт лишний логарифм. Лучше алгоритм Мо с изменениями (трёхмерный Мо): поддерживаем массив cnt[value] для текущего отрезка, а в каждом запросе перебираем делители $x$ и смотрим cnt[d] за $O(1)$. Итого $O(n^{5/3}) + \sum (\text{число делителей})$.

1.6. Герои и монстры

Монстры в ряд, у каждого здоровье $hp_i$ (до $10^9$) и урон $d_i$. Герой с параметрами (здоровье, урон $g$, оба до $2\cdot10^5$) сражается с монстрами по очереди: за раунд каждый наносит урон другому. Для каждого героя — сколько монстров он убьёт.

Монстр $i$ живёт $\lceil hp_i/g\rceil$ раундов и за это время наносит $d_i\cdot\lceil hp_i/g\rceil$ урона. Делим монстров на блоки; для каждого блока и каждого $g$ хотим знать суммарный урон блока. Сортируем монстров блока по $hp$ и для фиксированного $g$ перебираем значение $k=\lceil hp/g\rceil$: монстры с таким $k$ образуют отрезок в отсортированном порядке, их вклад — $k$ умноженное на сумму $d$ на этом отрезке. По всем $g$ это гармонический ряд: $\sum_g C/g = O(C\log C)$. Запрос проходит блоки целиком, пока герой жив, а в «смертельном» блоке — по одному монстру.

Альтернатива из зала: значение $\lceil hp_i/g\rceil$ как функция $g$ меняется не больше $2\sqrt{hp_i}$ раз — можно перебирать $g$ по возрастанию, обрабатывать события изменения и искать момент смерти по блокам из $\sqrt{n}$ сумм.

Напоминание: базовые строковые алгоритмы

2.1. Префикс-функция

$\pi_i$ — длина наибольшего собственного суффикса префикса $s[0..i]$, равного префиксу всей строки. Ключевое свойство: $\pi_i\le\pi_{i-1}+1$ — иначе, отрезав последний символ, получили бы более длинный подходящий суффикс у $s[0..i-1]$. Если $s_i = s_{\pi_{i-1}}$, то $\pi_i=\pi_{i-1}+1$. Иначе берём следующий по длине кандидат $\pi_{\pi_{i-1}-1}$ и повторяем.

vector<int> prefixFunction(const string& s) {
    int n = s.size();
    vector<int> p(n, 0);
    for (int i = 1; i < n; i++) {
        int k = p[i - 1];
        while (k > 0 && s[i] != s[k]) k = p[k - 1];   // следующий кандидат
        if (s[i] == s[k]) k++;
        p[i] = k;
    }
    return p;
}

Время $O(n)$: значение $k$ растёт не больше чем на 1 за шаг, а каждая итерация while его уменьшает.

2.2. Z-функция

$z_i$ — длина наибольшей подстроки, начинающейся в позиции $i$ и равной префиксу строки. Поддерживаем самый правый найденный отрезок совпадения $[l, r)$. Если $i\ge r$, сравниваем символы честно. Если $i<r$, то $s[i..r)$ совпадает с $s[i-l..r-l)$, поэтому можно начать с $\min(r-i,\ z_{i-l})$ и дальше сравнивать честно, сдвигая $r$.

vector<int> zFunction(const string& s) {
    int n = s.size();
    vector<int> z(n, 0);
    for (int i = 1, l = 0, r = 0; i < n; i++) {
        if (i < r) z[i] = min(r - i, z[i - l]);       // знаем по зеркальной позиции
        while (i + z[i] < n && s[z[i]] == s[i + z[i]]) z[i]++;
        if (i + z[i] > r) l = i, r = i + z[i];        // сдвигаем самый правый отрезок
    }
    return z;
}

Время $O(n)$: каждое успешное сравнение сдвигает $r$ вправо. Обе функции в большинстве задач взаимозаменяемы, но префикс-функция нужна для понимания Ахо–Корасик. Поиск всех вхождений $s$ в $t$: строим $s\#t$ и ищем позиции, где функция равна $|s|$.

2.3. Алгоритм Манакера

Подстрок-палиндромов может быть $O(n^2)$, поэтому для каждого центра (символа — для нечётных палиндромов, промежутка — для чётных) храним длину наибольшего палиндрома с этим центром. Любой меньший с тем же центром тоже палиндром, так что общее число палиндромов — сумма этих длин (делённых пополам).

Подсчёт устроен как у Z-функции. Поддерживаем самый правый найденный палиндром. Если центр $i$ вне его — расширяем честно. Если внутри — смотрим на зеркальную позицию $j$: если её палиндром не доходит до границы большого, у $i$ ответ тот же; если доходит — начинаем с него и расширяем честно. Время $O(n)$. Чётный случай можно не писать отдельно: вставим между всеми символами один и тот же новый символ (например, #), и все палиндромы станут нечётными. При подсчёте количества не забудьте вычесть палиндромы, состоящие из одних вставленных символов.

Алгоритм Ахо–Корасик

3.1. Задача и идея

Даны строки $t_1,\ldots,t_n$ и большая строка $s$. Для каждой $t_i$ найти все её вхождения в $s$ (гарантируется, что вхождений суммарно немного). Для одной строки это делает префикс-функция: она для каждой позиции $s$ хранит наибольший суффикс, равный префиксу $t$. Для многих строк будем хранить наибольший суффикс пройденной части $s$, который является префиксом хоть какой-то из строк $t_i$. Все префиксы набора — это вершины бора, поэтому состояние — вершина бора.

Договоримся: вершине бора соответствует строка, написанная на пути от корня до неё.

3.2. Суффиксные ссылки

Суффиксная ссылка $link(v)$ — вершина, соответствующая наибольшему собственному (не равному самой строке) суффиксу строки $v$, который есть в боре. Ссылка корня — сам корень. Например, в боре строк $\{aa, ab, ba, bab, bb, \ldots\}$ ссылка вершины $bab$ ведёт в $ab$, вершины $aa$ — в $a$.

Префикс-функция — это суффиксные ссылки в боре из одной строки («бамбуке»): там ссылки всегда ведут в предков. В общем боре ссылка может вести в совсем другую ветку.

3.3. Как считать ссылки

Пусть $u$ — ребёнок $v$ по символу $c$. Откинем последний символ: любой подходящий суффикс $u$ без последнего символа — суффикс $v$, который есть в боре. Поэтому $|link(u)| \le |link(v)|+1$. Кандидаты перебираем от длинного к короткому: $w = link(v)$, затем $link(w)$, и так далее. Первый $w$, у которого есть переход по $c$, даёт ответ: $link(u) = go(w, c)$. Если дошли до корня и перехода нет — $link(u)$ = корень.

// для вершины u = go[v][c]; ссылка v уже посчитана
if (v == root) link[u] = root;                 // у детей корня ссылка — корень
else {
    int w = link[v];
    while (w != root && go[w][c] == -1) w = link[w];   // следующий кандидат
    link[u] = (go[w][c] != -1) ? go[w][c] : root;
}

Ссылка всегда ведёт в строго более короткую строку. Поэтому вершины обрабатываем в порядке возрастания глубины — BFS по бору: когда считаем $link(u)$, ссылки всех более коротких вершин уже готовы.

3.4. Почему это быстро

Каждый прыжок $w\gets link(w)$ уменьшает глубину кандидата хотя бы на 1. После $k$ неудачных прыжков получаем оценку $h(link(u)) - 1 \le h(link(v)) - k$, то есть $k\le h(link(v)) - h(link(u)) + 1$. Просуммируем по всем рёбрам на пути от корня к концу одной строки $t_i$: разности $h(link(\cdot))$ сокращаются телескопически, и остаётся не больше $|t_i|$. Каждое ребро бора лежит на пути какой-то строки, поэтому суммарно все прыжки занимают $O\left(\sum|t_i|\right)$.

3.5. Проход по строке $s$ и все вхождения

Отметим в боре терминальные вершины — концы строк $t_i$. Идём по $s$, поддерживая вершину $v$ — наибольший суффикс пройденного, лежащий в боре. Переход по символу $c$ — точно как при подсчёте ссылок: пока из $v$ нет перехода по $c$ и $v$ не корень, прыгаем по ссылке; потом переходим, если можем. Суммарно это $O(|s|)$ по тому же телескопическому рассуждению.

Все строки набора, оканчивающиеся в текущей позиции, — это терминальные вершины на пути по ссылкам от $v$ до корня. Ходить по всем ссылкам долго: многие вершины не терминальные. Поэтому введём сжатую (терминальную) ссылку $exit(v)$ — ближайшая терминальная вершина, достижимая из $v$ хотя бы одним прыжком по ссылкам (или $-1$). Считается вместе со ссылкой: если $link(v)$ терминальная, то $exit(v)=link(v)$, иначе $exit(v)=exit(link(v))$.

for (int i = 0; i < (int)s.size(); i++) {
    int c = s[i] - 'a';
    while (v != root && go[v][c] == -1) v = link[v];
    if (go[v][c] != -1) v = go[v][c];
    // все строки набора, заканчивающиеся в позиции i
    for (int u = term[v] ? v : exitLink[v]; u != -1; u = exitLink[u])
        occ[id[u]].push_back(i - depth[u] + 1);    // начало вхождения
}

Время — $O\big(\sum|t_i| + |s| + \text{число вхождений}\big)$.

Полезная оценка. Различных длин у строк набора не больше $\sqrt{2\sum|t_i|}$, ведь $1+2+\ldots+k\le\sum|t_i|$. Поэтому если строки различны, из каждой позиции $s$ сжатые ссылки ведут не больше чем через $O(\sqrt{\sum|t_i|})$ терминальных вершин, и вхождений всего $O(|s|\sqrt{\sum|t_i|})$. Эту оценку стоит держать в голове.

3.6. Первое вхождение каждой строки

Нужно для каждой $t_i$ только первое вхождение. Идём так же, но если терминальная вершина уже получила ответ, то и все терминальные выше неё по сжатым ссылкам уже обработаны — когда мы проходили её в первый раз, мы поднялись по всей цепочке. Поэтому после прохода цепочки её можно «отрезать»: например, обнулить сжатую ссылку у пройденных вершин. Каждое сжатое ребро пройдём не больше одного раза, итого $O\big(\sum|t_i| + |s|\big)$.

3.7. Количество вхождений каждой строки: дерево ссылок

Теперь вхождений может быть очень много (все $t_i$ — строки из букв a, и $s$ тоже). Заметим: если оставить только вершины бора и суффиксные ссылки (направленные «вверх»), получится дерево с корнем в корне бора. Из каждой вершины, кроме корня, ровно одна ссылка, и циклов нет, потому что длина строго уменьшается. То же верно для сжатых ссылок на терминальных вершинах (если считать, что $-1$ — это корень).

Проход по $s$ в каждой позиции добавлял бы $+1$ всем терминальным вершинам на пути от $v$ до корня этого дерева. Тогда число вхождений $t_i$ — сколько раз «поток» прошёл через её вершину. Значит, достаточно в каждой позиции сделать cnt[v]++ только в текущей вершине, а в конце ответ для $t_i$ — сумма cnt в поддереве её вершины в дереве ссылок (один DFS). Время $O\big(\sum|t_i|+|s|\big)$.

Онлайн-версия. Строки $s_j$ приходят по очереди, и после каждой нужно ответить для заданного набора индексов, сколько раз соответствующие $t_i$ входят в $s_j$. Делаем эйлеров обход дерева ссылок; «$+1$ в вершине» — точечное прибавление в дереве Фенвика, а «сумма в поддереве» — сумма на отрезке эйлерова обхода. Каждое действие за $O(\log)$. Вместо Фенвика можно строить сжатое дерево по вершинам, затронутым запросом.

3.8. Автомат Ахо–Корасик

Вместо того чтобы каждый раз прыгать по ссылкам в цикле, заранее посчитаем для каждой вершины $v$ и каждого символа $c$ переход $trans(v,c)$ — куда мы попадём, стоя в $v$ и прочитав $c$. Если в боре есть ребро по $c$, это оно; иначе это $trans(link(v), c)$ (а для корня — корень). Получается автомат из $O(\sum|t_i|\cdot\Sigma)$ переходов, где $\Sigma$ — размер алфавита.

Всё считается в том же BFS. Когда достаём вершину $v$, её ссылка уже готова — считаем все $trans(v,\cdot)$. Затем для каждого ребёнка $u=go(v,c)$: $link(u) = trans(link(v), c)$ (а для детей корня — корень). Так ссылки считаются вообще без циклов while.

queue<int> q;
link[root] = root;
q.push(root);
while (!q.empty()) {
    int v = q.front(); q.pop();
    for (int c = 0; c < 26; c++) {
        int u = go[v][c];
        if (u != -1) {
            link[u] = (v == root) ? root : trans[link[v]][c];
            trans[v][c] = u;
            q.push(u);
        } else {
            trans[v][c] = (v == root) ? root : trans[link[v]][c];
        }
    }
}

Семинар

4.1. Строки без запрещённых подстрок

Даны строки $s_1,\ldots,s_n$. Сколько существует строк длины $m$, не содержащих ни одну из них как подстроку? Нужно $O\big(\sum|s_i|\cdot m\cdot\Sigma\big)$.

Строим автомат Ахо–Корасик. Строка содержит запрещённую подстроку ровно тогда, когда при проходе мы оказываемся в «плохой» вершине: терминальной или такой, из которой по ссылкам достижима терминальная. Удаляем плохие вершины. Автомат детерминированный, поэтому каждой строке соответствует ровно одна вершина, в которой мы окажемся. $dp[len][v]$ — число строк длины $len$, приводящих в вершину $v$; переход — по каждому символу в $trans(v,c)$, если она не плохая. Ответ — $\sum_v dp[m][v]$.

4.2. Бесконечная строка без запрещённых подстрок

Существует ли бесконечная строка без запрещённых подстрок? Удаляем плохие вершины автомата; бесконечная строка — это бесконечное блуждание по оставшемуся графу переходов, а оно существует тогда и только тогда, когда в нём есть цикл, достижимый из корня. Ищем цикл DFS-ом. Граф переходов автомата — не дерево: переходы $trans$ могут вести «назад» по ссылкам.

4.3. Бор на битах

Число можно записать двоичной строкой фиксированной длины (от старшего бита) и положить в бор. У каждой вершины не больше двух детей — по 0 и по 1.

  • Максимальный XOR с $x$ в множестве. $2^k > 2^{k-1}+\ldots+2^0$, поэтому выгоднее всего отличаться от $x$ в старшем возможном бите. Спускаемся от корня и на каждом уровне идём в ребёнка с битом, противоположным биту $x$, если он есть; иначе — в другого.
  • XOR всех чисел с $x$ и поиск mex. Копим общий XOR $y$ лениво. Единичный бит $k$ в $y$ означает, что на глубине $k$ дети меняются местами — учитываем это при спуске, ничего не меняя в боре. Для mex храним размеры поддеревьев: если поддерево на глубине с $k$ оставшимися битами полное (размер $2^k$), mex не в нём, идём в другое.
  • Отрезок с максимальным XOR. Через префиксные XOR: $a_l\oplus\ldots\oplus a_r = pref_r\oplus pref_{l-1}$. Идём по $r$, ищем в боре префиксов максимальный XOR с $pref_r$ и добавляем $pref_r$ в бор. Так же считается количество отрезков с XOR не больше $k$: спуск по бору с размерами поддеревьев.

4.4. Максимальный общий префикс со строкой из отрезка

Даны строки $s_1,\ldots,s_n$. Запросы онлайн: строка $t$ и отрезок $[l,r]$ — найти максимальную длину общего префикса $t$ со строкой $s_i$, $l\le i\le r$.

Без $[l,r]$ — просто спуск по бору, пока есть нужное ребро. С отрезком нужно проверять: есть ли в поддереве следующей вершины строка с индексом из $[l,r]$. Храним в каждой вершине отсортированный вектор индексов строк, проходящих через неё, и проверяем бинпоиском (lower_bound). Кажется, что памяти много (на «бамбуке» векторы длины $1,2,3,\ldots$), но индекс строки $i$ записан ровно в $|s_i|$ вершин её пути, так что суммарный размер векторов — $\sum|s_i|$. Ответ на запрос — $O(|t|\log n)$.

4.5. Двумерный поиск с одной ошибкой

Даны таблица $T$ размера $n\times m$ и образец $S$ размера $s\times t$. Найти все позиции, где $S$ входит в $T$ с не более чем одной несовпадающей клеткой. Нужно линейное время.

Одномерно. Строка $s$ входит в $t$ с одной ошибкой, начиная с позиции $i$, если совпадающий префикс длины $x$ (Z-функция от $s\#t$) и совпадающий суффикс длины $y$ (Z-функция на развёрнутых строках) вместе с одной ошибкой покрывают всю длину: $x+y+1\ge|s|$.

Двумерно. Нарезаем $S$ на строки, одинаковым строкам даём один номер, и строим на них Ахо–Корасик. Проходим им по каждой строке $T$ и записываем в клетку номер строки $S$, которая в ней заканчивается (если есть). Теперь для каждого столбца клеток получаем последовательность номеров, и задача становится одномерной: последовательность номеров строк $S$ должна входить в столбец «с одной ошибкой» — префикс строк совпал, одна строка не совпала, суффикс совпал. Но несовпавшая строка может отличаться больше чем в одной клетке. Поэтому то же самое делаем и по столбцам (транспонировав обе таблицы): если в позиции и по строкам, и по столбцам вышло совпадение с одной ошибкой, то несовпадающая клетка ровно одна. Всё работает за линейное время от размера входа.

4.6. Добавление строк в Ахо–Корасик

Запросы: добавить строку в набор; для строки $t$ найти суммарное число вхождений всех добавленных строк. Ахо–Корасик не умеет добавлять строки — его можно только построить заново.

Приём «степени двойки». Храним несколько автоматов, у каждого число строк — степень двойки, и все размеры различны. Ответ на запрос — сумма ответов всех автоматов (запросы к ним независимы). Новая строка — автомат размера $2^0$. Пока есть два автомата одного размера $2^k$, сливаем их: собираем все строки и строим автомат размера $2^{k+1}$ заново. Каждая строка переезжает в больший автомат не больше $\log n$ раз и при каждой перестройке стоит свою длину, поэтому суммарно перестройки занимают $O\big(\sum|s_i|\log n\big)$. Приём годится для любой структуры с операциями «построить» и «независимый запрос».
