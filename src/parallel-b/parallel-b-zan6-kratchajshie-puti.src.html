Занятие начинается с разбора контеста по деревьям отрезков (лектор называет его «разбором в порядке возрастания сложности»). Задача C: независимо по битам

Решение сводится к одной фразе: задачу решают независимо по каждому биту. Для младшего бита, для следующего и так далее строится своё дерево отрезков, в вершине которого хранится информация для нулей и единиц. Ответ получается объединением результатов по всем битам. Тот же приём используется для любых побитовых операций: операции над разными разрядами между собой не связаны.

Задача D: копирование отрезков между массивами

Условие (как напомнил лектор). Даны два массива. Операция: взять отрезок второго массива и скопировать его в некоторое место первого. Запросы — узнать значение элемента первого массива.

Что хранить в дереве. В дереве отрезков хранятся индексы копируемых элементов второго массива. Если в позиции записано число $j$, значит, в этой позиции первого массива сейчас лежит $b_j$; значение $-1$ означает, что позиция не менялась и там осталось исходное число.

Чтобы скопировать отрезок, на заданном диапазоне первого массива нужно проставить арифметическую прогрессию с шагом $1$. Например, при копировании первых трёх элементов второго массива проставляются значения $0, 1, 2$; при копировании элементов со второго по четвёртый — $1, 2, 3$. Тогда запрос в первом массиве возвращает индекс элемента второго массива: если он равен $-1$, берём исходное число, иначе берём число из второго массива по этому индексу.

Проставление арифметической прогрессии разбиралось на предыдущей лекции. Так как шаг всегда один, в массовой операции достаточно хранить только первое число прогрессии (оно не всегда ноль).

Задача G: объединение прямоугольников

Задача разбиралась на лекции; лектор напоминает, что её можно решать двумя способами.

Задача F: три операции, всё сводится к арифметической прогрессии

В задаче три операции на дереве отрезков. Первая — прибавление числа на отрезке. Вторая — прибавление «шатра»: в центре отрезка прибавляется большое значение $X$, а в обе стороны оно убывает с шагом $d$. Фактически это две арифметические прогрессии: одна с шагом $+d$, вторая с шагом $-d$, причём вторая начинается с максимального значения $X$, а начало первой вычисляется ().

Прибавлять арифметическую прогрессию на отрезке умеем; остаётся «докрутить» операцию обычного прибавления. Лайфхак: представить обе операции как одну и ту же массовую операцию. Прибавление числа на отрезке — это прибавление арифметической прогрессии с шагом ноль. Поэтому все операции в дереве — это прибавление арифметической прогрессии, а запрос $get$ делается как обычно. Участник уточняет, что шаг прогрессии не обязан быть единицей; лектор отвечает, что от этого только проще — всё сводится к прибавлению арифметической прогрессии.

Задача E: сортировка подсчётом на отрезке

Условие. Дана строка и запросы «отсортировать подстроку на отрезке» ().

Используется сортировка подсчётом: на отрезке считаем количество символов каждого вида, затем присваиваем отрезки нужных символов. Лектор предлагает сравнить два варианта ():

  1. Одно дерево отрезков, в вершине которого хранится 26 чисел — количество каждого символа.
  2. 26 деревьев отрезков, каждое из которых отвечает за один символ (): там хранятся нули и единицы («здесь стоит этот символ»), нужны присваивание на отрезке и сумма на отрезке.

Во втором варианте для запроса сначала в каждом из деревьев выполняется $get$ — сколько символов этого вида на отрезке; затем в каждом дереве отрезок зануляется; затем в нужных деревьях нужный отрезок заполняется единицами.

Асимптотика. В первом варианте каждый запрос стоит $26 \cdot \log n$ на каждую операцию (в каждой посещённой вершине пересчитываются все $26$ чисел), а таких операций тоже $26$; итого размер алфавита в квадрате на логарифм: $O(26^2 \log n)$. Во втором варианте нет штрафа за пересчёт всех значений в каждой вершине: получается $O(26 \log n)$ на запрос. Второй вариант заходит точно и проще пишется (нули и единицы); первый, по словам лектора, тоже можно «упихать».

Урок. Иногда стоит следить за тем, сколько стоит одно слияние (merge) в вершине: если оно долгое, это влияет на асимптотику.

Задача H: НОД на отрезке при прибавлении

Запросы: прибавить число на отрезке и найти $\gcd$ на отрезке.

Идея. НОД набора чисел равен НОД любого одного числа из набора и всех чисел его разностного массива: $$\gcd(a_l, a_{l+1}, \dots, a_r) = \gcd\bigl(a_l,\ a_{l+1} - a_l,\ \dots,\ a_r - a_{r-1}\bigr).$$ Пример лектора: числа $7, 21, 49$ при разностях $14, 28$ дают $\gcd = 7$; если к разностям добавить, например, $49$, НОД остаётся равным $7$ (–).

Решение. Храним два дерева отрезков.

  • Первое хранит разностный массив. Прибавление $x$ на отрезке $[l, r]$ превращается в два обновления в точке: в левой границе плюс $x$, в правой минус $x$ (). Запрос — НОД на отрезке; он вычисляется как любая другая операция (функция «взять НОД левого и правого поддерева»). Это возможно именно потому, что обновление только точечное: для массового обновления нормального push здесь придумать нельзя.
  • Второе хранит исходный массив с обычными массовыми операциями (). Оно нужно, чтобы брать значение одного элемента отрезка и добавить его в НОД. Без него, например, при $7, 21, 49$ получился бы НОД разностей $14$ ().

Задача: взятие по модулю, присваивание и сумма

Запросы: взять числа на отрезке по модулю, присвоить значение, найти сумму на отрезке. Лектор напоминает идею, разобранную на лекции ():

Ключевое наблюдение. При взятии числа по модулю есть два варианта: либо оно не изменилось (было меньше модуля), либо уменьшилось хотя бы вдвое. Значит, без присваиваний каждое число изменилось бы не более $\log C$ раз ($C$ — максимальное значение), и всего изменений было бы не более $n \log C$.

Присваивание ничего не ломает. Присваиваний не более $Q$, поэтому в структуру за всё время попадёт не более $N + Q$ чисел ($N$ — исходные, $Q$ — верхняя граница тех, что будут присвоены), и каждое из них сократится не более $\log C$ раз. Итого операций модуля, меняющих числа, не более $(N+Q)\log C$.

Как реализовать. Есть два варианта.

  1. Явный. На отрезке находим максимум спуском; если он меньше модуля, операция заканчивается; иначе заменяем найденное число на нужное и повторяем (). Но тогда каждый спуск стоит $\log n$, и общая сложность умножается на $\log n$.
  2. За один спуск (). Если в текущей вершине максимум поддерева меньше модуля, менять в ней нечего. Если максимум не меньше модуля, спускаемся рекурсивно в обоих поддеревьях, обновляем их и пересчитываем текущую вершину. Асимптотически то же самое — работа пропорциональна числу изменённых вершин, — но константа гораздо лучше: один запрос на все вершины, а не отдельный запрос на каждое число; и пишется проще.

Задача: сколько отрезков накрывает хотя бы одну из заданных точек

Есть набор отрезков. В запросе приходит набор точек, нужно найти число отрезков, накрывающих хотя бы одну из них ().

Идея. Заранее посчитать для каждой точки, сколько отрезков её покрывает (это делается сканирующей прямой). Но просто сложить эти числа нельзя: отрезок, накрывающий сразу две точки, посчитается дважды. Поэтому идём по точкам слева направо и в каждой считаем только новые отрезки () — те, которые накрывают текущую точку и не накрывают предыдущую. Если отрезок накрывает текущую точку и уже был учтён, он гарантированно накрывает и предыдущую.

Новые отрезки = (все отрезки, накрывающие текущую точку) минус (отрезки, накрывающие весь промежуток между предыдущей и текущей точкой). Количество накрывающих точку известно, остаётся научиться отвечать на запрос: сколько отрезков накрывают весь диапазон $[L, R]$ ().

Как отвечать. Отсортируем отрезки по левой границе и выпишем их правые границы в этом порядке (). Тогда запрос «накрывают $[L, R]$» — это отрезки с левой границей $\le L$ (префикс этого массива, находится бинарным поиском) и правой границей $\ge R$ (). Остаётся посчитать на префиксе количество чисел $\ge R$: это делается Merge Sort Tree либо Wavelet Tree (). Вейвлет асимптотически быстрее, но MST тоже заходит.

Из чата. Участник предлагает более простое решение: спуск по дереву отрезков, где в вершине помечается, что в неё заходили; сбрасывать разметку между точками. Лектор говорит, что идейно оно легче, звучит нормально, но он его не сдавал и не может сразу подтвердить (). Сжимать координаты в этой задаче не нужно ().

Задача N: $k$-я порядковая статистика на отрезке

Нужно найти $k$-е по порядку число на отрезке. Первый шаг — бинарный поиск по ответу: нужно отвечать на вопрос «сколько на отрезке чисел меньше $x$».

  • Первое решение — MST. Получается $O(\log^2 n)$ на запрос MST, умноженное на $\log$ от бинпоиска, то есть $O(\log^3 n)$; этого достаточно.
  • Ускорение: заменить MST на Wavelet Tree. Тогда получается $O(\log n)$ от бинпоиска, умноженное на $O(\log n)$ запроса вейвлета, то есть $\log^2$.
  • И можно заменить бинарный поиск спуском по вейвлет-дереву — получится просто $O(\log n)$.

Лектор считает задачу «абсолютной халявой», хотя её сдали мало людей из-за тяжёлых условий.

Задача про исторический максимум

Условие. На отрезке операция «прибавить» и запрос «исторический максимум»: какое максимальное число когда-либо стояло на этих позициях ().

Это обычное дерево отрезков, в котором в вершине хранятся максимум и исторический максимум на отрезке.

В массовом обновлении без исторического максимума хранилось бы одно число: сколько добавить на отрезке — назовём его $add$. Теперь добавляется второе — $hadd$: максимальное значение добавки с момента предыдущего push (). Когда мы делаем push, исторический максимум «перетекает» в детей, и обе добавки обнуляются. Пока push не делается, при добавлении $x$ мы увеличиваем $add$ на $x$ и обновляем $hadd = \max(hadd,\ add)$.

Push. Лектор описывает его словами: при проталкивании сначала используем историческую добавку, затем обычную; ниже то же самое записано точно.

Развёрнутое объяснение. Пусть в вершине $v$ хранятся: $mx$ — текущий максимум, $hmx$ — исторический максимум, $add$ — отложенная добавка, $hadd$ — наибольшая «префиксная сумма» добавок с момента последнего push (то есть максимум из $0$ и всех частичных сумм). Чтобы применить к вершине пакет «добавка $a$, наибольшая частичная сумма которой $h$», достаточно четырёх присваиваний (порядок важен — сначала история, потом текущие значения): $$hmx \gets \max(hmx,\ mx + h),\quad mx \gets mx + a,\quad hadd \gets \max(hadd,\ add + h),\quad add \gets add + a.$$ push применяет к обоим детям пакет $(add_v,\ hadd_v)$ и обнуляет $add_v$, $hadd_v$. Обычная операция «прибавить $x$ на отрезке» применяет к полностью покрытой вершине пакет $(x,\ \max(x, 0))$. 
struct SegTree {
    int n;
    vector<long long> mx, hmx, add, hadd;
    // ... build: mx[v] = hmx[v] = a[l] в листе; pull: максимумы детей ...
    void apply(int v, long long a, long long h) {
        hmx[v]  = max(hmx[v],  mx[v]  + h);     // сначала история
        mx[v]  += a;                             // потом текущее значение
        hadd[v] = max(hadd[v], add[v] + h);
        add[v] += a;
    }
    void push(int v) {
        if (add[v] == 0 && hadd[v] == 0) return;
        for (int c : {2 * v, 2 * v + 1}) apply(c, add[v], hadd[v]);
        add[v] = hadd[v] = 0;
    }
    // update: если вершина целиком в отрезке — apply(v, x, max(x, 0LL)); иначе push, рекурсия, pull
    // query: исторический максимум — hmx[v] у полностью покрытых вершин, push при спуске
};
Проверено сравнением с перебором на 3 000 случайных массивов (до 40 операций каждый): ответы на запросы исторического максимума совпали.

Смысл задачи — показать, что в массовых операциях могут лежать нетривиальные величины и push может выглядеть нетривиально.

Из чата. Зачем в массовом обновлении хранить $hadd$? Пусть на отрезке стояли нули, мы сделали массовое «+5», затем «−5». Исторический максимум должен быть $5$. Но если ничего не пушили, текущая добавка равна $0$, и без отдельного $hadd$ эти две операции не были бы видны. Поэтому нужна «максимальная историческая префиксная сумма» добавок с момента последнего push. Если бы на моменте «+5» произошёл push, пятёрка уже ушла бы вниз.

Задача O: наименьшая сумма, которую нельзя набрать монетами на отрезке

Условие. Есть монеты с номиналами $a_i$. Запрос на отрезке: найти наименьшую сумму, которую нельзя набрать монетами этого отрезка ().

Сначала решаем задачу на всём массиве. Монеты рассматриваем в порядке возрастания номинала (порядок монет в массиве ни на что не влияет). Поддерживаем инвариант: умеем набирать ровно суммы от $1$ до $x$ и никакие другие. Изначально $x = 0$.

Рассмотрим очередную монету $y$.

  • Если $y > x + 1$, она не поможет: сумму $x+1$ набрать не получится. Если все оставшиеся монеты больше $x+1$, то ответ — $x + 1$ ().
  • Если $y \le x + 1$, монету использовать можно, и теперь набираются все суммы от $0$ до $x + y$ (). Почему: сумму $s \le x$ берём из прежнего набора; если $s > x$, берём монету $y$ и набираем $s - y$ из прежних, причём $0 \le s - y \le x$, так как $y \le x+1$ (–).

Запросы на отрезке. Начинаем с $x = 0$. На каждом шаге делаем запрос «сумма всех монет на отрезке со значением $\le x + 1$» () — это все монеты, которые могут пригодиться. Если сумма оказалась больше $x$, то $x$ становится равным этой сумме (). Важно присваивание «=», а не «+=»: эта сумма уже включает монеты, использованные ранее (). Если $x$ не изменился, ответ $x + 1$ ().

Сколько шагов. Не больше $2\log$ (по порядку величины — логарифм): пусть $x$ перешло в $x'$, затем в $x''$. В момент $x'$ уже использованы все монеты $\le x+1$; значит, при втором переходе добавилась монета, большая $x + 1$, и новая сумма не меньше $x + (x+1)$, то есть $\ge 2x$. За любые два перехода число удваивается, поэтому их не более $2\log C$ (–). Лектор отмечает, что эта оценка очень грубая.

Сумма монет $\le x+1$ на отрезке — это запрос «сумма чисел на отрезке не больше $v$»: MST или Wavelet Tree. MST проще пишется; вейвлет на практике ускоряет в два–три раза, а не в десятки (–).

Из чата. Откуда берётся условие «монеты $\le x+1$»? Если мы умеем набирать все суммы до $x$, полезны только монеты номиналом до $x+1$: монета $x+2$ не закрывает сумму $x+1$. Суммируем все такие монеты и говорим, что до этой суммы набирать умеем; повторяем, пока сумма не перестанет меняться.

Задача P: колода карт и запросы

Условие (как пересказал лектор). Колода карт задана перестановкой, например $1\ 4\ 3\ 5\ 2$. Дана последовательность запросов, например «3, 2, 2»: карты нужно получать именно в этом порядке. За одно действие можно взять верхнюю карту колоды и вставить её в любое место. Нужно минимизировать число действий, за которое выполняются все запросы (–).

Перефразировка. Очень важный шаг. Когда мы убираем карту, мы не вставляем её сразу в колоду, а откладываем в карман. Теперь за одно действие можно взять либо верхнюю карту колоды, либо любую карту из кармана. Позже строится последовательность действий, показывающая, что формулировки эквивалентны.

Жадность. Если нужная карта ещё лежит в колоде, берём карты сверху и откладываем их в карман, пока не получим нужную. Если нужная карта уже когда-то откладывалась, достаём её из кармана за одно действие. Так жадно симулируется весь порядок получаемых карт; ответ без восстановления — длина получившегося массива действий ().

Пример. Колода $1\ 4\ 3\ 5\ 2$, запросы $4, 5, 3, 4$. Идём до четвёрки: взяли $1$ и $4$. Хотим пятёрку: идём до пятёрки, выкидывая $3$ и $5$ (то есть откладываем их в карман). Тройка уже откладывалась — берём за одно действие. Четвёрка тоже откладывалась — берём за одно действие.

Восстановление: куда вставлять карту. Чтобы понять, куда в колоду надо сунуть карту, нужно посмотреть, когда она понадобится в следующий раз. Берём два её соседних вхождения в последовательность запросов и считаем количество различных чисел между ними (–). Ровно эти числа формируют «шапку» колоды до следующего появления нашей карты: они обязаны лежать выше (мы встретили их раньше), и ничего другого выше быть не может, иначе нам пришлось бы перебирать другие карты до нужной. Поэтому карту нужно вставить на глубину, равную числу различных на отрезке. Количество различных на отрезке считается MST или Wavelet Tree (–).

Другой взгляд: в каждый момент карты в колоде отсортированы по моменту, когда они в следующий раз будут использованы. Только что использованная карта должна лечь после тех, которые понадобятся раньше неё — отсюда тоже получается «число различных на отрезке» (–).

Задача B: параллелепипед и красные точки

Условие (как пересказал лектор). В трёхмерном пространстве даны точки, каждая помечена зелёной или красной: зелёные точки загаданный параллелепипед содержит, красные не содержит. Затем приходят независимые запросы — новая точка, и нужно ответить одно из четырёх: она обязательно входит в любой загаданный параллелепипед; обязательно не входит; может как входить, так и не входить; либо исходные данные некорректны (такая раскраска невозможна) (–). Трёхмерный Фенвик здесь не подходит из-за памяти ().

Проверка корректности. Строим минимальный возможный загаданный параллелепипед: по каждой оси берём минимум и максимум среди зелёных точек (независимо по каждой оси). Линейным проходом проверяем красные точки: если хотя бы одна попала внутрь, исходные данные некорректны ().

«Обязательно входит». Точка обязательно входит, если лежит в минимальном параллелепипеде (за $O(1)$ проверяется).

Различаем «обязательно не входит» и «может». Представим, что запрошенная точка тоже зелёная, и расширим минимальный параллелепипед до охватывающего зелёные точки и новую (по каждой оси берём минимум и максимум трёх значений). Если в расширенном параллелепипеде есть красная точка, то синяя зелёной быть не могла: «не может входить ни в какой загаданный». Если красных точек в нём нет, ответ «может» (–).

Итак, нужно отвечать на запрос «есть ли красные точки в трёхмерной области». В общем случае это сложно, но здесь любая запрошенная область содержит минимальный параллелепипед (он известен заранее и константен) ().

Разбиение на восемь частей. Область (расширенный параллелепипед минус минимальный) разбивается на восемь параллелепипедов: берём угол минимального параллелепипеда и противоположный угол расширенного и строим параллелепипед на этих двух точках. Всего восемь таких пар, и в объединении они дают расширенный параллелепипед (–). Нам достаточно, что красная точка нашлась хотя бы в одной из частей.

Оффлайн по группам. Для каждого запроса получаем по одному параллелепипеду в каждую из восьми групп, и в каждой группе у всех параллелепипедов общий угол — угол минимального параллелепипеда (). Именно этот факт позволяет отвечать на все запросы группы в оффлайне.

Ответ на запросы одной группы. Пусть общий угол перенесён в начало координат: нужно для каждого параллелепипеда с одним углом в $(0,0,0)$ понять, есть ли в нём красные точки (). Выбираем одну из осей и запускаем по ней сканирующую прямую: события — «добавляется точка» и «закрывается параллелепипед» (). После этого все запросы двумерные: добавление точки на плоскость и проверка, есть ли в области с углом в $(0,0)$ точки ().

Двумерный запрос решается одномерным деревом отрезков: по каждой строке храним самую левую точку (изначально $+\infty$). При добавлении точки делаем min= в точке. Чтобы проверить область, берём минимум на отрезке строк и сравниваем его с правой границей области (–).

Склеивать ответы не нужно. Запрос разбит на восемь частей, но объединять результаты не требуется: если в какой-то части нашлась красная точка, ответ записывается сразу в нужную позицию массива ответов (–). Лектор отмечает, что задача — скорее на реализацию, чем на идею ().

На этом разбор окончен; лектор напоминает, что остальные задачи контеста по идее несложные и пишутся легко, и объявляет начало лекции.

Кратчайшие пути: BFS, Дейкстра, Флойд

Лекцию читают два лектора по очереди. Первая часть — основы: BFS, алгоритм Дейкстры с доказательством, приёмы вокруг BFS и алгоритм Флойда. Вторую часть (Форд–Беллман, отрицательные циклы и неявные графы) рассказывает второй лектор после перерыва.

План

Сначала лектор «просто повторяет, как устроен BFS» (без доказательства), затем разбирает Дейкстру, и уже с доказательством становится ясно, как BFS и Дейкстра связаны (). Дальше — приёмы для BFS, затем Флойд, а потом второй лектор покажет поиск отрицательных циклов и ещё несколько задач на кратчайшие пути (–). Лектор предупреждает, что доказательства «будут на зачёте» ().

BFS и инвариант очереди

Обозначения. Есть стартовая вершина $S$, рёбра имеют длину один (граф пока считается неориентированным). Массив $D$ — это расстояния, которые мы подсчитываем; $\mathrm{dist}(v)$ — настоящее (оптимальное, кратчайшее) расстояние, известное «оракулу». Изначально $D[S]=0$ (–).

Релаксация (). Если для вершины $v$ расстояние уже посчитано, а $u$ — её сосед, то $$D[u]=\min\bigl(D[u],\;D[v]+w(v,u)\bigr).$$

В очереди BFS хранятся вершины $v_1,v_2,\dots,v_k$. Мы достаём первую вершину и помечаем её; пометка означает, что расстояние до неё больше не пересчитывается — мы утверждаем, что оно оптимально. После этого релаксируем её соседей (–).

Утверждение. Расстояния, записанные для вершин очереди, не возрастают в обратную сторону, то есть не убывают от начала к концу: $D[v_1]\le D[v_2]\le\dots$ (–). Доказывается индукцией ().

  • База. В очереди одна вершина $S$ — утверждение выполнено.
  • Шаг. Пусть после $k$ итераций очередь устроена так: сначала префикс вершин с одинаковым расстоянием $x$, потом суффикс вершин с расстоянием $x+1$ (–). Достаём первую вершину (расстояние $x$) и кладём в конец её непомеченных соседей с расстоянием $x+1$. Если очередь состояла целиком из $x+1$, то получается $x+1,\dots,x+1,x+2,\dots$ — это тот же вид с заменой $x\to x+1$; в остальных случаях мы просто откусываем один $x$ спереди и дописываем $x+1$ в конец (–).

Значит, расстояния в очереди всегда по неубыванию, и вершины достаются в порядке неубывания расстояний. Лектор подчёркивает, что это не доказательство корректности BFS, а замечание; корректность потом сводится к Дейкстре, потому что мы гарантировали: из очереди всегда достаётся наименьший элемент (–).

Дейкстра на set

Для Дейкстры нужно множество, из которого можно доставать минимум «вручную»; в BFS ребра весом один позволяют обойтись обычной очередью (–). Первый способ — set пар $(D[v],\,v)$ — расстояние, затем сама вершина (–).

Вопрос лектора: можно ли вызвать erase для значения, которого в множестве нет? Ответ — можно, ошибки не будет (). Поэтому релаксация записывается так: если $D[u]>D[v]+c$, то удаляем из множества пару $(D[u],u)$ (она может и отсутствовать), присваиваем $D[u]$ новое значение и вставляем пару заново (–).

Замечание лектора. Многие сначала кладут в set все расстояния, лишь бы не удалять отсутствующие элементы. Так писать не нужно: erase несуществующей пары безопасен. Про priority_queue лектор скажет отдельно.
// Дейкстра на set: храним пары (расстояние, вершина), при улучшении удаляем старую пару
vector<ll> dijkstra_set(int n, const vector<vector<pair<int,int>>>& g, int s) {
    vector<ll> d(n, INF);
    set<pair<ll,int>> q;
    d[s] = 0; q.insert({0, s});
    while (!q.empty()) {
        int v = q.begin()->second;
        q.erase(q.begin());                      // вершина помечена: d[v] окончательно
        for (auto [u, w] : g[v])
            if (d[u] > d[v] + w) {
                q.erase({d[u], u});              // erase несуществующей пары безопасен
                d[u] = d[v] + w;
                q.insert({d[u], u});
            }
    }
    return d;
}

Алгоритм — по аналогии с BFS: тот же пересчёт, а то, что каждый раз берётся минимум, обеспечиваем вручную.

Доказательство корректности Дейкстры

Утверждение: в тот момент, когда вершину достают из очереди и помечают, в ней записано корректное значение: $D[v]=\mathrm{dist}(v)$ (–). Доказываем индукцией по числу вынутых вершин.

Пусть уже вынуто $k$ вершин и для них инвариант выполнен. Достаём $(k+1)$-ю вершину $U$ — минимум очереди (–). Рассмотрим множество помеченных вершин; в нём лежит $S$, а $U$ — вне него (–). Возьмём кратчайший (оптимальный) путь из $S$ в $U$. Он идёт сначала по помеченным вершинам, а затем впервые заходит в непомеченную вершину — назовём её $X$, её предшественника на пути — $Y$ (–; позже, в –, лектор повторяет определение: $X$ — первая непомеченная вершина кратчайшего пути из $S$ в $U$).

Выпишем простые факты об этих вершинах.

  • Мы взяли именно $U$, то есть $U$ — минимум очереди, значит $D[U]\le D[X]$ (–).
  • Вершина $Y$ помечена, значит $D[Y]=\mathrm{dist}(Y)$ по предположению индукции; при её релаксации мы прорелаксировали ребро $YX$, поэтому $D[X]=D[Y]+w(Y,X)=\mathrm{dist}(X)$. Это верно, потому что префикс оптимального пути тоже оптимален (–; повторено в –).
  • $X$ лежит на префиксе пути до $U$, а веса неотрицательны, поэтому $\mathrm{dist}(X)\le\mathrm{dist}(U)$ (–).
$$D[U]\;\le\;D[X]\;=\;\mathrm{dist}(X)\;\le\;\mathrm{dist}(U)\;\le\;D[U].$$ Цепочка замкнулась, значит все её звенья равны и $D[U]=\mathrm{dist}(U)$ (–).
Развёрнутое объяснение. Последнее неравенство $\mathrm{dist}(U)\le D[U]$ верно всегда: $D[U]$ — длина какого-то реально найденного пути из $S$ в $U$, а $\mathrm{dist}$ — длина кратчайшего. Остальные три неравенства — это, по порядку, «$U$ — минимум», «$X$ прорелаксирована помеченной $Y$» и «$X$ раньше $U$ на кратчайшем пути». Если $X=U$, цепочка выше становится тривиальной.
Вопрос лектора. Почему это доказательство не работает при отрицательных рёбрах? Ломается неравенство $\mathrm{dist}(X)\le\mathrm{dist}(U)$: если на оставшейся части пути есть отрицательные рёбра, префикс до $X$ может оказаться длиннее всего пути (–). Лектор предлагает потренироваться в объяснении — такие вопросы будут в тесте (–).
Связь с BFS. Доказательство использует только то, что из очереди каждый раз достаётся минимум. В BFS это обеспечено монотонностью очереди (из-за весов 1), поэтому доказательство корректности BFS «буквально то же самое» (–).

Асимптотика Дейкстры

В реализации на set в очереди не более $n$ вершин, достаём по одной — $n\log n$, плюс $m$ релаксаций, каждая за $\log n$ (–): $$O\bigl((n+m)\log n\bigr).$$ Если граф полный ($m\approx n^2$), получается $O(n^2\log n)$, и этот логарифм «не к месту» — релаксация слишком долгая (–).

Как сделать релаксацию за $O(1)$, а минимум искать подольше. Оставим единственный массив расстояний; минимум будем искать обычным проходом по массиву, не забывая, что помеченные вершины пропускаются (–). Тогда релаксация — просто присваивание за $O(1)$, а минимум в массиве длины $n$ ищется $n$ раз: $$O(n^2+m).$$

// Дейкстра за O(n^2 + m): минимум ищем проходом по массиву
vector<ll> dijkstra_n2(int n, const vector<vector<pair<int,int>>>& g, int s) {
    vector<ll> d(n, INF);
    vector<char> used(n, 0);
    d[s] = 0;
    for (int it = 0; it < n; it++) {
        int v = -1;
        for (int i = 0; i < n; i++) if (!used[i] && (v == -1 || d[i] < d[v])) v = i;
        if (d[v] == INF) break;
        used[v] = 1;
        for (auto [u, w] : g[v]) d[u] = min(d[u], d[v] + w);
    }
    return d;
}
Замечание лектора. «Теперь пишем на очереди»: структура, которая нужна от set, очень узкая — вставка с сохранением порядка и взятие первого элемента. Есть структура, которая делает это чуть быстрее.

Дейкстра на priority_queue

Эта структура — priority_queue. Она умеет push и pop (добавить и достать первый элемент) (–). Одна особенность: очередь сортирует «в обратном порядке», сверху лежит наибольший элемент. Чтобы получить минимум, кладут расстояние с минусом или указывают компаратор greater (–).

Проблема. В set пара $(D,u)$ для вершины была одна, а в priority_queue вершину можно положить дважды — например, если её релаксировали две разные вершины $v_1,v_2$ (–). Лишнюю копию не хочется обрабатывать, поэтому при извлечении пары $(d,u)$ проверяем: если $d\ne D[u]$, то пара устарела — делаем continue (–).

Из обсуждения. Кто-то предложил просто проверять, помечена ли вершина. Лектор объясняет: вершину могли прорелаксировать двумя способами, пока она не помечена; при первом извлечении берётся меньшее значение и вершина помечается, второе уже не меньше — это то же самое (–). Массив «помечено/нет» тоже годится.
// Дейкстра на priority_queue: дубликаты пропускаем проверкой d != d[v]
vector<ll> dijkstra_pq(int n, const vector<vector<pair<int,int>>>& g, int s) {
    vector<ll> d(n, INF);
    priority_queue<pair<ll,int>, vector<pair<ll,int>>, greater<>> q;   // минимум наверху
    d[s] = 0; q.push({0, s});
    while (!q.empty()) {
        auto [dv, v] = q.top(); q.pop();
        if (dv != d[v]) continue;                // устаревшая копия
        for (auto [u, w] : g[v])
            if (d[u] > d[v] + w) { d[u] = d[v] + w; q.push({d[u], u}); }
    }
    return d;
}

Асимптотика. Лектор выводит её в обсуждении с залом. В очереди может оказаться до $m$ записей, на каждую приходится вставка и извлечение за логарифм, итого $O(m\log m)$. Так как граф без петель и кратных рёбер, $m\le n^2$, поэтому $\log m\le 2\log n$ и обычно пишут просто $O(m\log n)$ (–). На практике это обычно быстрее, чем set (–).

Мелкие трюки для BFS

Своя очередь на массиве. Обычная queue в C++ — надстройка над deque, поэтому иногда работает долговато. Если известно, что в очередь попадёт не больше $n$ элементов, заводим массив размера порядка $n+1$ и храним границы $[L,R)$ полуинтервала: добавление в конец — q[R++] = x, удаление из начала — L++ (–). Работает быстрее; нужно редко, но лектору пригодилось (–).

Задача для тех, кому скучно. В Дейкстре используется очередь с приоритетами; обычная куча — двоичная (у каждой вершины два сына). Можно ли сделать кучу, где у каждой вершины около $n$ детей? Лектор замечает: тогда вставка и удаление становятся дешёвыми для одного из действий, а в предельном случае получается ровно «тупой» поиск минимума за $n$ (–). Подробнее про кучу лектор обещает рассказать, когда речь дойдёт до декартова дерева (–).

0-1 BFS и мультиисточник

Рёбра веса 0 и 1. Чтобы BFS работал, нужно только, чтобы очередь всегда была отсортирована: сначала «иксы», потом «иксы плюс один». Для этого вместо очереди берём дек: при релаксации по ребру веса $0$ вершину кладём в начало дека, по ребру веса $1$ — в конец. Инвариант сохраняется: слева всегда $x$, справа $x+1$ (–).

// 0-1 BFS на деке
vector<int> bfs01(int n, const vector<vector<pair<int,int>>>& g, int s) {
    vector<int> d(n, INT_MAX);
    deque<int> q; d[s] = 0; q.push_back(s);
    while (!q.empty()) {
        int v = q.front(); q.pop_front();
        for (auto [u, w] : g[v])
            if (d[u] > d[v] + w) {
                d[u] = d[v] + w;
                if (w == 0) q.push_front(u); else q.push_back(u);
            }
    }
    return d;
}

Ближайшая чёрная вершина. Граф, каждая вершина чёрная или белая; для каждой белой нужно найти расстояние до ближайшей чёрной. Два способа: (1) положить в очередь все чёрные вершины и запустить «мульти-BFS»; (2) завести фиктивную вершину, провести из неё рёбра длины $0$ во все чёрные и запустить BFS от неё. «По сути, это то же самое» — кому как понятнее (–).

Веса рёбер от 0 до K

Если веса рёбер — целые числа от $0$ до небольшого $K$, BFS тоже можно приспособить (если $K$ большое, запускают Дейкстру).

Способ 1. Разбить каждое ребро длины $x$ на $x$ рёбер длины один (с фиктивными вершинами) и запустить обычный BFS. Это работает плохо при большом $m$: вершин станет $n+\Theta(Km)$, и такой BFS работает за $O(n+Km)$ (–). «Иногда всё равно проходит».

Способ 2 (лектор сам его ни разу не писал: хватало лить рёбра). Заведём $K+1$ очередь — по аналогии с сортировкой подсчётом: первая очередь отвечает за расстояние $x$, вторая — за $x+1$, и т. д. до $x+K$ (–). Берём вершину из текущей очереди; релаксация по ребру длины $c$ кладёт вершину в очередь с номером $(D[v]+c)\bmod(K+1)$ — очереди зациклены (–). Помимо самих очередей храним номер той очереди, которую сейчас разбираем: пока в ней есть элементы, берём их, потом идём к следующей (–). Порядок «сначала $x$, потом $x+1$, …» мы поддерживаем вручную — «идея как в сортировке подсчётом» (–). Снова гарантируется, что мы всегда берём минимум, поэтому доказательство Дейкстры работает без изменений (–).

// BFS по весам 0..K на K+1 циклических очередях
vector<int> dial(int n, const vector<vector<pair<int,int>>>& g, int s, int K) {
    vector<int> d(n, INT_MAX);
    vector<queue<pair<int,int>>> q(K + 1);       // в очереди (расстояние, вершина)
    d[s] = 0; q[0].push({0, s});
    int pending = 1;                              // сколько записей лежит в очередях
    for (int cur = 0; pending > 0; cur = (cur + 1) % (K + 1)) {
        while (!q[cur].empty()) {
            auto [dv, v] = q[cur].front(); q[cur].pop(); pending--;
            if (dv != d[v]) continue;
            for (auto [u, w] : g[v])
                if (d[u] > d[v] + w) {
                    d[u] = d[v] + w;
                    q[d[u] % (K + 1)].push({d[u], u}); pending++;
                }
        }
    }
    return d;
}
Из обсуждения. Лектор просит не бояться: звучит страшно, но пишется легко. На вопрос о времени: при малом $K$ получается порядка $K\cdot n+m$ — всё равно быстрее, чем с логарифмом (–).
Развёрнутое объяснение. В коде выше в очередях хранятся пары «(расстояние, вершина)», а не одни вершины, потому что в одной очереди могут лежать и устаревшие записи: как и в priority_queue, их пропускаем проверкой dv != d[v]. Счётчик pending нужен, чтобы остановиться, когда все $K+1$ очередей пусты. Код проверен сравнением с обычной Дейкстрой на случайных графах.

Алгоритм Флойда

До сих пор мы считали расстояния из одной вершины и требовали неотрицательных рёбер. Иногда нужны расстояния между всеми парами вершин; запускать $n$ раз Дейкстру не оптимально — хочется переиспользовать информацию. «Динамику мы вам не просто так рассказывали» (–).

Простое $d[a][b]$ без дополнительного параметра не получается; нужен ещё один параметр. Пока в графе нет отрицательных рёбер (их «навернём за бесплатно» позже), кратчайший путь между $a$ и $b$ не повторяет вершин. Пусть $c$ — вершина пути с максимальным индексом (–). Определим $$dp_c[a][b]\;=\;\text{длина кратчайшего пути из }a\text{ в }b,\text{ все промежуточные вершины которого имеют индекс}\le c.$$

$$dp_c[a][b]=\min\bigl(dp_{c-1}[a][b],\;dp_{c-1}[a][c]+dp_{c-1}[c][b]\bigr).$$ Путь разбивается на участок от $a$ до $c$ и от $c$ до $b$ (–).

Порядок важен. Нельзя написать $dp[b][c]$ вместо $dp[c][b]$, если граф ориентированный: идём $a\to c\to b$ (–). Для Дейкстры и BFS ориентированность ничего не меняет (–). Перебор целиком — тройной цикл, время $O(n^3)$ (–).

Реализация. Внешний цикл по $c$ (в коде $k$), внутри перебираем $a$ и $b$, и $d[a][b]=\min(d[a][b],\,d[a][k]+d[k][b])$ (–). Слой хранить не нужно: между слоями $c-1$ и $c$ разница лишь в том, что на слое $c$ разрешена вершина $c$. Если мы «перетираем» слой на месте, ответ точно не станет хуже, а слои можно не хранить; и мы никак не конфликтуем с тем, что вершина $k$ может совпадать с $a$ или $b$ (–).

// Флойд: d[a][b] = min(d[a][b], d[a][k] + d[k][b]); k — внешний цикл
vector<vector<ll>> floyd(int n, const vector<vector<ll>>& w) {
    auto d = w;
    for (int k = 0; k < n; k++)
        for (int a = 0; a < n; a++)
            for (int b = 0; b < n; b++)
                if (d[a][k] < INF && d[k][b] < INF) d[a][b] = min(d[a][b], d[a][k] + d[k][b]);
    return d;
}

База. Нужно быть аккуратным с петлями: $d[a][a]$ равно нулю либо длине петли (если она отрицательна). Положительная петля не нужна (–). Если петля отрицательная — расстояние равно $-\infty$.

Отрицательные циклы во Флойде

Обычно нужно знать, до каких вершин можно «набрать как угодно маленькое значение»: из стартовой вершины $S$ можно попасть в отрицательный цикл, а из него — в вершину $T$ (–). Значит, нужно уметь находить вершины на отрицательных циклах и проверять достижимость $S\to x\to T$ (–).

Рассмотрим простой отрицательный цикл через вершину $x$. В какой-то момент Флойд пересчитывает $d[x][x]$ через промежуточную вершину $u$: $d[x][u]+d[u][x]$, и это в сумме даёт число меньше нуля. Поэтому вершины с $d[x][x]<0$ лежат на отрицательном цикле (–).

Важное дополнение. Лежать на простом отрицательном цикле — не то же самое, что иметь любое сколь угодно малое расстояние: если вершина достижима из отрицательного цикла, расстояние до неё тоже будет $-\infty$, хотя на цикле она не лежит. Поэтому, чтобы найти все такие вершины, нужно дополнительно учесть достижимость: пара $(S,T)$ имеет расстояние $-\infty$, если найдётся $x$ с $d[S][x]<\infty$, $d[x][x]<0$ и $d[x][T]<\infty$ (–).
Переполнение. Значения при отрицательных циклах «очень быстро переполняются» (лектор обещает дать в тесте пример). Поэтому вводят константу «минус бесконечность» и не даём значению опуститься ниже неё: d[a][b] = max(NINF, min(d[a][b], d[a][k] + d[k][b])) (–).
const ll INF = LLONG_MAX / 4, NINF = -INF;
// Флойд с отрицательными циклами: значения не опускаются ниже NINF
for (int k = 0; k < n; k++)
    for (int a = 0; a < n; a++)
        for (int b = 0; b < n; b++)
            if (d[a][k] < INF && d[k][b] < INF)
                d[a][b] = max(NINF, min(d[a][b], d[a][k] + d[k][b]));
// расстояние s -> t равно -бесконечности, если есть x:
//   d[s][x] < INF, d[x][x] < 0, d[x][t] < INF

Лектор советует сдать в контесте задачи на отрицательные циклы обоими способами — Фордом–Беллманом и Флойдом, — чтобы потренироваться (–). На вопрос из зала, будут ли потоки, лектор отвечает, что будут; а динамика такого рода «встречается много где, потому что это очень лёгкий способ считать динамику» (–). Дальше — перерыв ().

Форд–Беллман, отрицательные циклы и неявные графы

Вторую часть читает другой лектор. Он напоминает, что первый лектор рассказал Флойда, и переходит к алгоритму Форда–Беллмана (–).

Идея Форда–Беллмана

В чём уникальность BFS. В BFS мы знаем, в каком порядке нужно перебирать рёбра, чтобы обновлять расстояния. Усложним задачу: пусть у рёбер произвольные веса, не обязательно положительные — порядок рёбер нам теперь неизвестен (–). Дейкстра при отрицательных рёбрах не работает; её можно «починить», но для этого потребуется тот же Форд–Беллман (–).

Идея. Возьмём какую-нибудь перестановку рёбер и повторим её $m$ раз подряд; получится последовательность длиной $m^2$ (–). Тогда любой рёберно-простой путь встречается в ней как подпоследовательность: первое ребро пути берём из первой копии перестановки, второе — из второй и т. д. (–). Значит, если проходить рёбра в таком порядке и обновлять расстояние вдоль каждого, мы обязательно «поймаем» нужный порядок рёбер для любого кратчайшего пути. Более того, перестановка между блоками может быть другой — важно лишь, чтобы в каждом блоке были все рёбра (–).

Предположим, что отрицательных циклов нет. Тогда любой кратчайший путь содержит не более $n$ вершин: цикл неотрицательной длины можно выбросить, не увеличив расстояние (–). Поэтому достаточно $n$ блоков: $n$ раз пройти по всем рёбрам в любом порядке и вдоль каждого ребра $(u,v)$ сделать $d[v]=\min(d[v],\,d[u]+w)$ (–).

Зачем всё это. «Предположим, этого знания (порядка) у нас нет. Давай возьмём последовательность из рёбер, в которой любая перестановка встречается как подпоследовательность». Операция «взять минимум» сама себя не портит, поэтому лишние обновления не мешают (–). Лектор также говорит, что можно мыслить «оракулом», который знает нужную последовательность рёбер; мы её не знаем, поэтому перебираем всё сразу, а вместо факториала — одна длинная последовательность (–).

Время. Сначала лектор оценивает наивно как $nm^2$, но тут же замечает, что мы не проходим всю длинную последовательность целиком, а делаем $n$ проходов по $m$ рёбрам, то есть $$O(nm).$$ (–).

// Форд–Беллман: n-1 проходов по всем рёбрам; возвращает true, если достижимый из s отрицательный цикл
bool ford(int n, const vector<E>& e, int s, vector<ll>& d) {
    d.assign(n, INF); d[s] = 0;
    for (int it = 0; it < n; it++) {
        bool ch = false;
        for (auto& x : e)
            if (d[x.a] < INF && d[x.b] > d[x.a] + x.w) { d[x.b] = d[x.a] + x.w; ch = true; }
        if (!ch) return false;               // ничего не изменилось — дальше тоже не изменится
        if (it == n - 1) return true;        // изменение на n-м проходе: есть отрицательный цикл
    }
    return false;
}
Развёрнутое объяснение. В коде выше проходов не больше $n$, и на последнем, $n$-м проходе изменений быть не должно. Кратчайший путь содержит не более $n-1$ рёбер, поэтому $n-1$ проходов достаточно; если же $n$-й проход всё ещё что-то улучшает, то в графе есть отрицательный цикл, достижимый из $s$ (это то самое «больше $n$ итераций» из ). Код проверен сравнением с Флойдом на 4000 случайных графов с отрицательными рёбрами.

Лектор отмечает, что алгоритм хорош для разреженных графов ($m$ порядка $n$, а не $n^2$): тогда его время около $n^2$ (–).

Ускорения

  1. Досрочный выход. Если во время полного прохода по рёбрам ни одно расстояние не изменилось, то и дальше ничего не изменится (следующие проходы делают то же самое с тем же начальным состоянием), и цикл можно прервать (–). Тогда время — «максимальный (по числу рёбер) кратчайший путь, умноженный на $m$», а не $nm$ (–).
  2. Ациклический граф. Если граф без циклов, делаем топологическую сортировку вершин, склеиваем списки смежности в этом порядке и получаем топологический порядок рёбер; в таком порядке достаточно одного прохода (–).
  3. Очередь (аналог BFS). Положим в очередь вершины, расстояние до которых изменилось, и релаксируем рёбра, исходящие только из них. Отличие от BFS: в BFS вершину второй раз обрабатывать не нужно, а здесь нужно — если вершину кладут в очередь второй раз, значит, расстояние до неё строго уменьшилось (–). Лектор рисует пример, где вершину нужно вернуть в очередь уже после того, как она была обработана (–).
// Форд–Беллман на очереди (без отрицательных циклов)
vector<ll> spfa(int n, const vector<vector<pair<int,ll>>>& g, int s) {
    vector<ll> d(n, INF); vector<char> in(n, 0); queue<int> q;
    d[s] = 0; q.push(s); in[s] = 1;
    while (!q.empty()) {
        int v = q.front(); q.pop(); in[v] = 0;
        for (auto [u, w] : g[v])
            if (d[u] > d[v] + w) { d[u] = d[v] + w; if (!in[u]) { in[u] = 1; q.push(u); } }
    }
    return d;
}
Замечание лектора. По худшему времени версия на очереди не хуже исходной ($O(nm)$), но на случайных графах работает почти за линию (–). BFS — это тот же Форд–Беллман с гарантией, когда и куда класть вершины; здесь гарантии нет, и появляется лишний множитель, который исчезает на случайном графе (–). Если граф непонятно как устроен (строится из условия с кучей ограничений), его особенности нельзя явно сформулировать, но он в целом похож на случайный — можно перемешать рёбра и сдать этот вариант: он обычно работает за линию (–). Лектор обещает рассказать в конце года, где именно в жизни встречается место, в котором велят писать именно это (–).
Обозначения. Стандартно: $V$ — множество вершин, $E$ — множество рёбер, $n=|V|$, $m=|E|$; $S$ — старт, $T$ — терминальная вершина («$F$ не стандартно, обычно $T$») (–).

Поиск отрицательного цикла

Как искать цикл отрицательного веса с помощью Форда–Беллмана? Гораздо проще, чем кажется: если мы сделали больше $n$ итераций, цикл есть, если меньше — нет (–). Цикл по итерациям продолжается, пока что-то обновляется, то есть пока есть кратчайший путь строго такой длины; а отрицательный цикл существует тогда и только тогда, когда есть «кратчайший путь любой длины, сколь угодно большой» (–).

Как найти сам цикл. Нужно хранить массив предков — откуда обновилось минимальное расстояние — и найти цикл в нём (–).

Цикл минимального среднего веса

Задача. В ориентированном графе найти цикл, у которого средний вес ребра (сумма весов, делённая на число рёбер) как можно меньше (–). Перебирать циклы бесполезно: их может быть очень много. Лектор приводит пример графа из цепочки пар вершин, где можно выбрать любое подмножество пар и «наворачивать крюк» (–).

Идея. Минимум искать напрямую мы не умеем, но умеем проверять, что минимум меньше нуля — то есть есть отрицательный цикл (–). Поэтому делаем бинарный поиск по ответу: вычитаем кандидата из веса каждого ребра. Средний вес любого цикла уменьшается ровно на это число (–). Теперь проверяем, появился ли цикл отрицательного веса: если минимальный средний вес меньше кандидата, то после вычитания отрицательный цикл гарантированно есть; если больше — отрицательных циклов нет (–). Общая идея: если вы умеете проверять «минимум меньше $K$» для фиксированного $K$, то $K$ можно «подвинуть» вычитанием из всех рёбер (–).

Проверка отрицательного цикла — Флойдом или Фордом–Беллманом; суммарно получается $\log C\cdot n^3$ (–).

// Флойд на double: есть ли цикл отрицательного веса (d[x][x] < 0)
bool has_neg(int n, vector<vector<double>> d) {
    for (int k = 0; k < n; k++) for (int a = 0; a < n; a++) for (int b = 0; b < n; b++)
        d[a][b] = min(d[a][b], d[a][k] + d[k][b]);
    for (int i = 0; i < n; i++) if (d[i][i] < -1e-12) return true;
    return false;
}
double min_mean(int n, const vector<vector<double>>& w, double lo, double hi) {
    for (int it = 0; it < 60; it++) {
        double mid = (lo + hi) / 2;
        auto d = w;
        for (auto& r : d) for (auto& x : r) x -= mid;       // вычитаем кандидата из всех рёбер
        if (has_neg(n, d)) hi = mid; else lo = mid;
    }
    return lo;
}
Проверка. Код выше (двоичный поиск по ответу + Флойд на дробных весах с проверкой $d[x][x]<0$) сверен с перебором всех простых циклов на 300 случайных графах из 2–6 вершин: расхождение меньше $10^{-6}$. Границы поиска lo и hi нужно выбирать так, чтобы ответ лежал между ними, например от минимального до максимального веса ребра.

Цикл минимального веса. Если рёбра неотрицательные, то после Флойда минимальный цикл ищем как минимум по парам вершин $x\ne y$ суммы $d[x][y]+d[y][x]$: так в цикле заведомо хотя бы две вершины и он нетривиален (–). Отрицательный случай тривиален — расстояние равно $-\infty$.

Неявный граф и дерево отрезков

Последняя задача — на неявный граф. Обычно граф задан матрицей или списками смежности, а здесь он задан так: из вершины $u$ есть ребро весом $w$ во все вершины с индексами от $l$ до $r$. Рёбер получается очень много, но их можно описать отрезками (–). Нужно найти расстояния от одной вершины до всех. Лектор отмечает: любая задача решается за квадрат, но мы хотим быстрее, примерно за $(n+m)\log n$ (–, –).

Совет лектора. «Когда граф задан неявно, надо придумать Дейкстру — так же, как любая интерактивная задача — это бинарный поиск». Это, по словам лектора, верно «в среднем».

В Дейкстре с set проблемы с самим множеством нет, проблема в том, чтобы быстро перебрать рёбра (–). Лектор обсуждает с залом несколько идей — перебирать рёбра в порядке уменьшения расстояния, хранить для отрезков веса, искать на отрезке «все, которые можно уменьшить» (–) — и приходит к такой схеме.

Дерево отрезков вместо множества. Храним в дереве отрезков в точке $v$ текущее расстояние до $v$ (–). Раз расстояние и так хранится в дереве, доставать минимум можно не из множества, а из корня дерева (–). Релаксация по ребру $u\to[l,r]$ с весом $w$ — это операция «$\min=\,D[u]+w$ на отрезке $[l,r]$» (–). Лектор замечает, что обычное дерево отрезков с массовой операцией — сложная структура, а у нас частный случай: нужно лишь получать минимум (–).

В вершине дерева хранится текущий минимум и модификатор (как в массовых операциях). Пусть мы пришли в вершину с операцией «$\min=x$» (–). Лектор разбирает два случая:

  • Если минимум в вершине не больше $x$, минимум на отрезке не изменится; достаточно заменить модификатор на $\min$(старый модификатор, $x$) и вернуться (–).
  • Если минимум больше $x$, то после операции минимум на отрезке станет равен $x$; это тоже фиксируется в модификаторе, и мы возвращаемся (–). При запросах («get») модификатор спускается вниз.
Важное дополнение. Лектор объясняет эти случаи сокращённо. Чтобы алгоритм был корректным, в реализации ниже обе ветки объединены: при операции «$\min=x$» в вершине всегда делаем mn = min(mn, x) и tag = min(tag, x), а модификатор при спуске применяется к обоим детям. Тогда каждая листовая вершина отрезка действительно получит значение $\min(D,x)$, а не только та, в которой «лежит» минимум.

Как не доставать одну вершину дважды. Когда вершина вынута из дерева, её нужно «выбросить». Лектор предлагает: при взятии минимума спуститься к листу и записать в него специальный флаг («$-1$»), который при подсчёте минимума игнорируется — для вершины-флага минимум считается нейтральным, как $+\infty$, но флаг не перезатирается операциями «$\min=$» (–). В общем случае так можно игнорировать не одно число, а любое условие (–).

Время. Каждое ребро-отрезок — одна массовая операция $O(\log n)$, а каждая вершина вынимается один раз и «закрывается» за $O(\log n)$; минимум из корня достаётся за $O(1)$. Получаем $$O\bigl((n+m)\log n\bigr)$$ (–).

// Дерево отрезков для неявной Дейкстры: chmin на отрезке и вынимание минимума
struct Seg {
    static constexpr ll DEAD = LLONG_MAX;   // метка «вершина уже вынута»
    int n; vector<ll> mn, tg;
    Seg(int n) : n(n), mn(4 * n, INF), tg(4 * n, INF) {}
    void app(int v, ll x) { if (mn[v] != DEAD) { mn[v] = min(mn[v], x); tg[v] = min(tg[v], x); } }
    void push(int v) { if (tg[v] < INF) { app(2*v, tg[v]); app(2*v+1, tg[v]); tg[v] = INF; } }
    void chmin(int v, int l, int r, int a, int b, ll x) {
        if (b < l || r < a) return;
        if (a <= l && r <= b) { app(v, x); return; }
        push(v); int m = (l + r) / 2;
        chmin(2*v, l, m, a, b, x); chmin(2*v+1, m+1, r, a, b, x);
        mn[v] = min(mn[2*v], mn[2*v+1]);
    }
    int take(int v, int l, int r) {          // вынуть вершину с минимальным d, пометить её DEAD
        if (l == r) { mn[v] = DEAD; return l; }
        push(v); int m = (l + r) / 2, res;
        if (mn[2*v] <= mn[2*v+1]) res = take(2*v, l, m); else res = take(2*v+1, m+1, r);
        mn[v] = min(mn[2*v], mn[2*v+1]);
        return res;
    }
};
// ребро-отрезок: из вершины во все вершины l..r с весом w
struct SE { int l, r; ll w; };
// Дейкстра по неявному графу
vector<ll> dijkstra_implicit(int n, const vector<vector<SE>>& g, int s) {
    Seg t(n); vector<ll> d(n, INF);
    t.chmin(1, 0, n - 1, s, s, 0);
    for (int it = 0; it < n; it++) {
        if (t.mn[1] >= INF) break;             // осталось только недостижимое
        ll dv = t.mn[1];
        int v = t.take(1, 0, n - 1);
        d[v] = dv;
        for (auto& e : g[v]) t.chmin(1, 0, n - 1, e.l, e.r, dv + e.w);
    }
    return d;
}
Реализация. Код выше записан по описанной идее: «закрытая» вершина получает метку DEAD (в коде это наибольшее возможное значение, чтобы метка не побеждала при взятии минимума и не перезатиралась операцией chmin), а недостижимая пока вершина хранит обычное «бесконечное» расстояние. Реализация проверена сравнением с Дейкстрой по явно развёрнутым рёбрам на 3000 случайных графов.
Ограничение. Всё это только для ориентированных рёбер. В неориентированном случае при каждом обновлении хотя бы одной вершины отрезка пришлось бы обновлять расстояние до $u$ — «а вот это сложно» (–).

Вопросы после лекции (по деревьям отрезков)

Лекция закончилась; лекторы остались отвечать на вопросы, пока участники решали контест. Вот вопросы, относящиеся к материалу.

Как ускорить «количество меньших на отрезке» в дереве с отсортированными списками (merge sort tree). Обычно запрос разбивают на $O(\log n)$ отрезков и в каждом делают бинарный поиск — это $O(\log^2 n)$ (–). Чтобы получить $O(\log n)$, во время построения при слиянии списков детей для каждой позиции запоминаем, где стояли указатели в левом и правом ребёнке. Тогда достаточно одного бинарного поиска в корне, а в детях позиция берётся готовым указателем (–). Это называется каскадированием; на практике это «суперрабочая» оптимизация (–).

Про память. Хранить vector внутри каждой вершины плохо: динамические массивы лежат в памяти как попало. Лучше один большой массив, а в вершине — левый и правый указатель на её кусок; слияние тогда пишет результат в позицию $[L_C,R_C)$ (–). Обновления такая структура не выдерживает (все указатели сдвигаются) (–).

Множество, в котором вставок сильно больше, чем запросов lower_bound. Тогда его выгодно сделать корневой декомпозицией: один счётный массив и для каждого блока длины порядка $\sqrt{n}$ — количество элементов. lower_bound и порядковая статистика идут сначала по блокам, потом внутри блока — $O(\sqrt{n})$; а обновление — $O(1)$: мы меняем одну ячейку и счётчик блока (–).

Дальше в курсе будет алгоритм «корневой по запросам» — отрезки группируют по блоку, в котором лежит левая граница (алгоритм Мо) (–). На этом занятие заканчивается.
